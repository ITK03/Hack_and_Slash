# Hack & Slash — 開発計画書

スマートフォン縦画面向け、Diablo 系ハック&スラッシュの開発計画。

---

## 0. 前提と方針

### 0.1 決定事項

| 項目 | 決定 | 理由 |
|---|---|---|
| ベース | Diablo 1 の構造 + Diablo 2 のアイテム + Diablo 3/4 の戦闘感 | 「シナリオ不要 / 現代でウケる」条件に最適 |
| プラットフォーム | Web (PWA)、スマホ縦画面 | 無料で配布可能、即座に実機確認できる |
| 技術 | TypeScript + Canvas2D + Vite | ランタイム依存ゼロ、軽量、無料 |
| 視点 | アイソメトリック (2:1 ダイヤ、64×32px タイル) | 原作準拠の見た目 |
| 操作 | 左＝仮想スティック / 右＝スキルボタン | 縦画面の両手親指操作に最適 |
| 進め方 | フェーズ分割・都度コミット | 軌道修正しやすく手戻りが小さい |
| ホスティング | GitHub Pages (Actions で自動デプロイ) | 無料 |

### 0.2 アセットについて

Diablo の実グラフィック・音源・テキストは著作権物のため同梱しない。
**ゲームシステム（仕様）は忠実に再現し、アセットは全て自前生成**する。

- 初期はコードによる手続き生成スプライト（色分けされたシルエット）
- レンダラはスプライトレジストリ経由で描画するため、後から本番アセットへ
  差し替えてもゲームロジックに一切影響しない

### 0.3 コンセプト

> **シナリオ無し・無限降下型ハクスラ。**
> 潜る → 殺す → 拾う → 強くなる → もっと深く潜る。

シナリオを削ることは欠点ではなく、現代のモバイル ARPG（Diablo Immortal、
Rift 系コンテンツ、ローグライト）が実証した最も中毒性の高い形式に一致する。
1 プレイ 5〜15 分で完結し、進行が永続する。

## 1. 画面設計（縦画面）

基準解像度 390×844 CSS px（iPhone 14 相当）、`env(safe-area-inset-*)` 対応。

```
┌─────────────────────────────┐
│ [HP▬▬▬▬]  B12F  [MP▬▬▬▬] [≡]│ ← ステータスバー
│ ▬▬▬▬▬▬ EXP ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬ │
├─────────────────────────────┤
│                        ┌───┐│
│                        │mini││ ← ミニマップ（トグル）
│                        └───┘│
│      ゲームビュー           │
│      (アイソメトリック)     │ ← Canvas
│                             │
│                             │
│                             │
├─────────────────────────────┤
│              ○ ○            │
│   ╭───╮     ○   ○   [◉]     │ ← 左:仮想スティック
│   │ ● │        [❤][💧]      │   右:スキル4 + 通常攻撃 + ポーション2
│   ╰───╯                     │
└─────────────────────────────┘
```

- **仮想スティック**: フローティング式。画面左半分のどこをタッチしても
  そこが原点になる。デッドゾーン + 8/16方向スナップ設定あり
- **スキルボタン**: クールダウンを円形ゲージで表示、コスト不足時はグレーアウト
- **UI 実装**: HTML/CSS の DOM オーバーレイ（Canvas の上）
  - 理由: スクロール可能なインベントリ、ツールチップ、セーフエリア、
    フォント描画が Canvas 実装より圧倒的に低コスト
  - ゲーム世界のみ Canvas
- **左利き対応**: 設定で左右反転

## 2. アーキテクチャ

```
src/
  main.ts                 エントリポイント、ブートストラップ
  core/
    loop.ts               固定タイムステップ(60Hz) + 描画補間
    rng.ts                決定的 RNG (mulberry32)、シード管理
    math.ts               ベクトル、補間、角度
    entity.ts             軽量エンティティ + システム（フル ECS は過剰）
    events.ts             型付きイベントバス
    input.ts              マルチタッチ、仮想スティック、ボタン
    save.ts               localStorage + IndexedDB、スキーマ版管理
    scene.ts              Title / Town / Dungeon / Death の遷移
  render/
    iso.ts                アイソメ座標変換、深度ソート
    camera.ts             追従、スムージング、クランプ
    sprites.ts            手続き生成スプライト、OffscreenCanvas キャッシュ
    layers.ts             地面/影/エンティティ/エフェクト/ライトの多層描画
    lighting.ts           放射状ライト、松明、視界
    fx.ts                 パーティクル、ヒットフラッシュ、画面揺れ
  game/
    stats.ts              ステータス、派生値計算
    combat.ts             命中判定、ダメージ計算、抵抗、クリティカル
    ai.ts                 敵 AI ステートマシン、群れ制御
    pathfind.ts           A* + パス平滑化
    skills.ts             スキル実行エンジン
    items.ts              アイテム生成、装備
    affixes.ts            接頭辞/接尾辞ロール
    loot.ts               ドロップテーブル、スマートルート
    dungeon/              各生成アルゴリズム
    progression.ts        経験値、レベル、パラゴン、難易度
    town.ts               町、商人、スタッシュ
  ui/                     DOM オーバーレイ UI
  data/                   モンスター、アイテム、アフィックス、スキル定義表
```

**設計原則**

- ゲームロジックは描画から完全に独立（テスト可能・ヘッドレス実行可能）
- 全ての数値はデータテーブル（`data/`）に集約し、コードにベタ書きしない
- 乱数は必ず注入された RNG 経由。同一シードで同一ダンジョンを再現できる

## 3. フェーズ計画

各フェーズ末で動作する状態にしてコミットする。

### Phase 0 — 基盤 `動く土台`

- Vite + TypeScript (strict) プロジェクト初期化、vitest 導入
- 固定タイムステップのゲームループ + 描画補間
- Canvas のリサイズ / devicePixelRatio / セーフエリア対応
- マルチタッチ入力層、仮想スティック、ボタン
- 決定的 RNG、シーン管理
- CI（型チェック + テスト）と GitHub Pages デプロイの Actions

**完了条件**: スマホで開くと縦画面にフィットし、スティック入力が画面に反映される

---

### Phase 1 — 描画と移動 `歩ける`

- アイソメトリック投影とタイルマップ描画
- Y ソートによる深度ソート（画家のアルゴリズム）
- カメラ追従（スムージング、境界クランプ）
- 手続き生成スプライト（8方向、待機/歩行アニメ）
- 衝突判定（タイル + 円形の押し出し）
- A* 経路探索 + 直線ショートカット判定

**完了条件**: 障害物のあるアイソメ空間をキャラクターが滑らかに歩ける

---

### Phase 2 — 戦闘コア `殴れる`

- **ステータス**: STR / DEX / VIT / ENE → 派生値
  - ダメージ、命中値、防御力、最大HP/MP、ブロック率、回復速度
- **戦闘計算**（Diablo 2 準拠）
  - 命中率 = f(攻撃者命中値, 防御側防御力, レベル差)、上下限クランプ
  - ダメージロール → 物理軽減 → 属性抵抗（火/氷/雷/毒）→ クリティカル
  - 継続ダメージ、状態異常（スタン / スロー / 凍結 / ノックバック）
- **アニメーション**: ステートマシン（待機/歩行/攻撃/被弾/死亡）+ 判定発生フレーム
- **敵 AI**: 索敵 → 追跡 → 攻撃 → 逃走、リーシュ、群れの分離ステアリング
- **遠距離/術者の敵**: 投射物、詠唱と予兆表示
- ダメージ数値のポップアップ、ヒットストップ、画面揺れ

**完了条件**: 敵と殴り合って、どちらかが死ぬ

---

### Phase 3 — スキルとクラス `技が撃てる`

3 クラス。それぞれ異なるリソース機構を持たせる（現代 ARPG の定石）。

| クラス | リソース | 特徴 |
|---|---|---|
| Warrior | Fury（攻撃で生成・消費） | 近接、耐久、突進 |
| Rogue | Energy（自動回復） | 遠距離/機動、罠、連射 |
| Sorcerer | Mana（低速回復、大容量） | 属性魔法、範囲殲滅、脆い |

- データ駆動のスキル定義（コスト、CD、詠唱時間、形状、係数、効果）
- 形状プリミティブ: 近接扇 / 投射物 / 貫通 / 設置 / 範囲 / ダッシュ / バフ
- クラスあたり 6 スキル（通常攻撃 1 + アクティブ 5）、ホットバーに 4 装備
- スキルレベルによる係数成長

**完了条件**: 3 クラスそれぞれが固有の戦闘リズムで戦える

---

### Phase 4 — アイテムとルート `拾える・強くなる`

ハクスラの心臓部。ここに最も時間を使う。

- **ベースアイテム**: 武器（剣/斧/鎚/短剣/杖/弓/ポールアーム）、
  防具（兜/鎧/篭手/靴/ベルト/盾）、装飾（指輪×2/首飾り）
- **レアリティ**
  | 等級 | アフィックス数 | 備考 |
  |---|---|---|
  | Normal | 0 | ベース性能のみ |
  | Magic | 1〜2 | 接頭辞/接尾辞 各1 |
  | Rare | 3〜6 | ランダム名生成 |
  | Legendary | 固有効果 + ランダム | ビルドを変える1行 |
  | Set | セット効果 | Phase 6 |
- **アフィックスシステム**（Diablo 2 準拠）
  - 接頭辞/接尾辞プール、アイテムレベルによる出現段階（tier）ゲート
  - 重み付き抽選、ベースタイプごとの許可グループ
- **アイテムレベル**: モンスターレベル由来。スマートルート（クラス寄せ）
- **インベントリ**: 60 スロットのフラット式（タップで装備）
  - Diablo 2 のグリッド式は縦画面では操作性が悪いため不採用
  - 装備中との性能差分を色付きで即時比較表示
- **ドロップ演出**: 地面にラベル表示、金貨とポーションは自動取得
- **通貨と消耗品**: 金貨、回復/マナポーション、帰還の巻物

**完了条件**: 敵を倒すとアイテムが落ち、拾って装備するとキャラが強くなる

---

### Phase 5 — ダンジョン生成 `潜れる`

- **テーマ別生成アルゴリズム**（10 階ごとに切り替え）
  | テーマ | アルゴリズム |
  |---|---|
  | Cathedral | 部屋 + 廊下（Diablo 1 の原アルゴリズム相当） |
  | Catacombs | BSP 分割 + 広間 |
  | Caves | セルオートマトン（有機的な洞窟） |
  | Hell | 迷路と部屋の混成 |
- **検証**: 生成後に到達可能性を必ず検査（全部屋が階段から到達可能）
- **配置物**: 扉、宝箱、樽、石棺、本棚、**シュライン**（一時バフ/呪い）
- **モンスター配置**: 階層に応じた種類、群れ、パック
- **エリート/レアモンスター**（Diablo 3 系アフィックス）
  - 凍結 / 電撃 / 分裂 / 盾持ち / 壁生成 / 拘束 / 再生 / 爆散 …
  - 現代的な「戦闘の毎回違う感」を最も安く生む要素
- **ボス**: 5 階ごと。予兆付きの大技、複数フェーズ
- **視界と光源**: 探索済みマップ、フォグ、放射状ライティング
- 階段（上/下）、町への帰還ポータル

**完了条件**: 無限に潜れて、階層ごとに違う地形と敵が出る

---

### Phase 6 — メタ進行とエンドゲーム `繰り返せる`

- **町ハブ**: 武器屋 / 魔女 / 治療師 / ギャンブラー / スタッシュ
- **難易度階梯**: Normal → Nightmare → Hell → Torment I〜XVI 相当
  - 敵の HP・ダメージ・アフィックス数と、ドロップ品質が同時に上昇
- **パラゴン**: レベル上限後の無限成長（少量のステータスを永続加算）
- **リフト**: 制限時間付きの高密度チャレンジ階層 + 報酬
- **ソケットとジェム**: 装備に埋め込み、取り外し
- **エンチャント**: アフィックス 1 つを再抽選（金貨と素材を消費）
- **分解と売却**: 不要装備を素材化
- **ウェイポイント**: 到達済み階層へ直行
- **セーブ**: 自動保存、スキーマ版管理、ハードコアモード（死亡＝消滅）

**完了条件**: 「もう一周」が成立し、数十時間の進行曲線が存在する

---

### Phase 7 — 演出と仕上げ `製品になる`

- パーティクル（血、火花、魔法）、被弾・死亡演出
- **音**: WebAudio による手続き生成 SFX + 簡易 BGM シンセ（著作権クリア）
- 触覚フィードバック（`navigator.vibrate`）
- 設定画面: 音量、描画品質、操作レイアウト、左右反転、方向スナップ
- **最適化**: オブジェクトプール、レイヤ分割描画、スプライト事前生成
  - 目標: iPhone SE 2 / ミドルレンジ Android で 60fps
- PWA 化（manifest、Service Worker、オフライン動作、ホーム画面追加）

**完了条件**: 実機で快適に遊べ、URL を共有すれば誰でも遊べる

## 4. テスト戦略

トークンと時間を無駄にしないため、**壊れると発見が遅い箇所だけ**自動化する。

| 対象 | 手法 | 理由 |
|---|---|---|
| ダンジョン生成の到達可能性 | vitest（1000 シード検証） | 詰みバグは手動発見が困難 |
| アフィックス抽選の分布 | vitest | 確率バグは目視で気づけない |
| ダメージ計算式 | vitest | 数値バランスの土台 |
| セーブ/ロードの往復 | vitest | 破損時の被害が最大 |
| RNG の決定性 | vitest | 再現性の前提 |
| 画面表示・操作 | Playwright（モバイル viewport でスクリーンショット） | 実機確認の代替 |

Chromium はこの環境に導入済みのため、Playwright による縦画面スクリーンショット
検証を各フェーズで実施できる。

## 5. パフォーマンス目標

| 指標 | 目標 |
|---|---|
| フレームレート | 60fps（ミドルレンジ端末） |
| 同時描画エンティティ | 200 体 |
| 初回ロード | 3 秒以内 |
| バンドルサイズ | 500KB 未満 |

主要な手法: レイヤ分割 Canvas（静的な地面は再描画しない）、
オブジェクトプール、スプライトの事前ラスタライズ、視錐台カリング。

---

## 6. リスクと対策

| リスク | 対策 |
|---|---|
| スコープ肥大で完成しない | フェーズ末で必ず遊べる状態にする。各フェーズ独立 |
| 縦画面で視界が狭すぎる | Phase 1 でズーム倍率を実機検証し、タイルサイズを確定 |
| Canvas2D の描画性能不足 | Phase 1 で 200 体のストレステストを実施。不足なら WebGL へ移行（描画層のみ差し替え） |
| バランス調整が終わらない | 全数値をデータテーブル化。調整はコード変更を伴わない |
| アセット差し替え時の手戻り | スプライトレジストリで抽象化済み |
