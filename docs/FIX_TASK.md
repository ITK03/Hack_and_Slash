## 手順0（最優先・これを最初にやる）

**成果物を push すること。** 前回はローカルに commit しただけで GitHub に届いておらず、
**誰も中身を確認できませんでした**。これが最大の問題です。

```bash
git remote -v                       # origin が無ければ次を実行
git remote add origin https://github.com/ITK03/Hack_and_Slash.git
git push -u origin HEAD:refs/heads/codex-fix
```

- 認証が通らない場合は **その場で報告して止まること。** 先に進んでも成果が届かない。
- push できたら、**ブランチ名とコミットハッシュを報告に書く。**
- 以降の修正も、作業の区切りごとに push する。**溜めない。**

## 手順2: 検査を最後まで回す

前回「`check-balance` が14分以上返らない」として打ち切っていますが、**これは異常ではありません。**
ボス床の死亡率を別枠で測るようになったため、**今は15〜20分かかります。ハングではないので待つこと。**

```bash
node scripts/check-prototype.mjs
node scripts/check-daily.mjs
node scripts/check-progression.mjs
node scripts/check-breakthrough.mjs
node scripts/check-balance.mjs      # 15〜20分。打ち切らない
node scripts/check-consumables.mjs  # 数分
node scripts/check-bundle-b.mjs     # 10〜20分。打ち切らない
node scripts/check-elements.mjs     # 数分
```

- **時間で打ち切らないこと。** 打ち切ったものは「未確認」であって「成功」ではない。
- 途中で落ちたら、**そのエラー全文**を報告に貼る。
- Playwright が無くて `check:layout` / `check:playable` / `check:ui` が
  スキップされる場合は、**「スキップした」と明記**する。通ったことにしない。

## 手順3: 前回の判断を見直す

前回の報告で自分で決めた次の2点を、**測り直して再判断**すること。

1. **大地砕きの持続火力。** 「薙ぎ払いの約14%だが全周と気絶があるので変更しない」と判断しているが、
   その根拠は倍率÷再使用時間だけで、**MPを織り込んでいない**。
   薙ぎ払い 12MP/0.55秒＝21.8MP/秒、大地砕き 34MP/5.0秒＝6.8MP/秒 で、
   **どちらもMP回復（3.4/秒）を上回る**ので、実際にはMPが律速になる。
   → **MP回復を含めた実戦での毎秒ダメージ**を実測し、その値で再判断して報告する。

2. **希少敵のHPの伸び。** 深度1/25/100で 10/19/29 は、
   「深く行くほどHPが高くなる」という要求に対して**平坦すぎないか**を再検討する。
   撃破時間 4.0/7.6/11.6秒 が、その深度で立ち止まる危険に見合っているかを
   周囲の敵の攻撃力と併せて実測し、判断を報告する。

## 守ること（再掲・前回守られていない可能性がある）

- **外部ライブラリを足さない。** ビルド工程も増やさない。`public/index.html` 単体で動くこと。
- **検査スクリプトにゲーム本体の式・定数・確率を書き写さない。**
  必ず `public/index.html` を読み込んで、その中の関数と状態を呼んで計測する。
- **目標値・検査内容を緩めて通さない。** 通らないなら、通らなかった事実と実測値を出す。
- **判断を求められていない箇所の仕様を勝手に変えない。**
  変えたのなら、変えた事実と理由を報告に必ず書く。
- `docs/SPEC.md` を、変更内容と**理由**で更新する。
