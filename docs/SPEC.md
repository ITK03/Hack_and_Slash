# Descent 仕様書

> 対象: `public/index.html`。本書は実装変更のたびに更新する。

## 検証の原則
- 検証スクリプトにゲーム本体の式・定数・確率を書き写してはならない。
- 必ず `public/index.html` を実行し、その中の関数と状態を呼び出して計測する。実行環境は `scripts/game-env.mjs` の `loadGame()` が提供する。
- 検査に外部依存を追加してはならない。`game-env.mjs` は Node 標準の `vm` と最小限の DOM スタブだけでゲーム本体を評価する。ブラウザもネットワークも不要で、`npm install` に失敗する環境でも `npm run check` は完走する。
- 時間の経過が要る検査は実時間を待たない。`game.advance(ms)` で仮想時間を進め、`setTimeout` / `setInterval` を決定的に発火させる。ポインタ操作は `game.dispatch(id, type, init)` で実際にイベントを配送する。
- 大量の試行を回した後に操作系を検査する場合は、先に `game.clearTimers()` で未発火のタイマーを切り離す。仮想時間が進まないまま積み上がった登録が一斉に発火して状態を壊すため。
- 「特定の文字列がファイルに存在するか」だけの確認は検証とみなさない。
- `npm run check` が通らない状態で完了報告してはならない。
- 目標を満たせない場合は、満たせなかった事実と実測値をそのまま報告する。目標値・探索範囲・チェック内容を緩めて通すことは禁止する。
- 計測が目標を外れたときは、まず「ゲームが壊れている」のか「計測方法が実態と合っていない」のかを切り分ける。基準を動かしてよいのは後者と確認できた場合だけで、そのとき何をどう確かめたかを併記する。
- 操作モードを比較する計測では、モードごとに移動の与え方を変えない。条件が揃っていない比較は数値が出ても意味を持たない。

## 画面構成（拠点タブ、ダンジョン HUD、ポップアップ）
- 初回は戦士/魔術師のクラス選択と操作訓練を行い、以後は拠点から潜行する。
- 拠点下部は「拠点」「装備」「倉庫」「商店」「設定」の5タブ。
- 拠点タブ本文は編成・持ち込み・任務/記録への短縮導線だけを置く。「次にできること」カードは置かない。開始深度、装備適性、次のボスは固定出撃バーへ集約する。
- 開始深度は到達済みの1F〜最深層を1層単位で自由入力できる。入力欄の左右には−5 / ＋5を置き、遠い層は直接入力、微調整は5層刻みで済ませる。到達済みの最深に張り付いて潜っている間は、深度が伸びたら開始深度も自動で追従させる（浅い深度を明示的に選んでいる人の設定は動かさない）。1Fのまま保存された古いセーブは読み込み時に最深へ寄せる。
- 出撃操作はタブバーの上に常駐する2段の出撃バーへ置き、拠点タブでは常に画面内に見えるようにする。上段は装備適性と次ボス、下段は−5 / 自由入力 / ＋5 / 潜るとする。入力と潜るボタンの高さを揃え、ボタンが上下へずれないグリッドにする。
- 日替わり任務は進捗バー付きの1行で表示し、受け取れる時だけボタンを出す。未達成の項目に押せないボタンを置かない。
- 拠点と装備の本文は常にスクロールできること。1画面に収まる前提で `overflow:hidden` を掛けると、内容が増えたときに画面外の項目へ手が届かなくなる（任務が開けなくなっていた）。
- 最上部にはプロフィールアイコン・表示名・最大深度・所持通貨を出す。表示名は端末内だけの自由入力にする（共有時にアカウントが見えないため）。ゴールドとジェムは桁区切り込み12桁を省略せず表示できる幅を最低値とする。
- 最上部の数字には、それが何かを引ける口を必ず持たせる。所持通貨の行は押せるようにし、押すと各項目の意味を出す。スタミナは `⚡` で表す（`▲` は形からは何も読めず、実際に「この三角は何？」と聞かれた）。
- アイコンと編成枠は、キャラクターの等級を枠の色で、職業を隅の印で示す。装備の「枠の色＝レア度」と読み方を揃える。
- 装備のマスには強化レベル（+N）と深度の両方を出す。強化レベルは強さを直接動かすのに、マスから読めなかった。
- 「装備中より強い」の▲は素の `score` ではなく実効値で判定する（職業不一致の減衰と無属性の上乗せ込み）。素の score で比べると、他職用の装備にまで▲が出る。
- 装備タブは「装備」「技」「能力」「限界突破」の4サブタブを持つ。一度「仲間」へ改称して 一覧 → その子 → やること の3段構成にしたが、装備を触るまでの手数が増えるとして差し戻した。**作業を先に選び、対象は上の帯で切り替える**のがこのゲームの形。
- 装備・技・能力のどのタブを開いていても、上部に「誰を編集中か」を出す。以前は装備タブの枠にしか出ておらず、技や能力の画面では手掛かりが無かった。
- キャラの切り替えは編成の面々を横並びにして1タップで移れるようにする。旧来は「職業を選ぶ → キャラを選ぶ」の2段階で、装備を見比べるだけでも往復が要った。編成外へ移るときは「変更」から一覧を開く。ボタンの名前は「変更」。「他のキャラ」では何が起きるのか読み取りにくい。
- 「誰を編集中か」は地の文に流さず、**枠付きの見出し**として出す。顔・「編集中」の見出し・名前・等級・職業/Lv/番手/戦闘力を1枚に収め、枠の左辺に等級の色を差す（装備の「枠の色＝レア度」と同じ読み方を人にも当てはめる）。切り替えボタンも同じ枠の中に置く。文字の大きさを本文と揃えて1行で流していたころは、他の説明に埋もれて読まれなかった。
- 倉庫に「道具」区画を置き、汎用素材・固有素材・道具を所持数つきで一覧する。何を何個持っているのかが分からないまま調合や持ち込みを決めさせない。
- 素材と道具は拾った時点で中身が確定しているので、**潜行中の戦利品画面にも同じ一覧を出す**（未鑑定の装備とは扱いが違う）。あわせて「今回いくつ拾ったか」を併記し、潜り続けるか帰るかの判断材料にする。
- 技ボタンの名前は、クールダウンと同じ場所（毎フレームの `updHUD`）で書く。名前だけ別経路で書いていたころは、キャラ交代時に「名前は前のキャラ・中身は次のキャラ」という食い違いが起き得た。
- キャラクター一覧は編成中のキャラを枠の順で先頭に並べ、「編成N番手」を出す。装備を触るのはたいてい編成中の面々なので、未編成のキャラに埋もれた状態で毎回探させない。職業一覧も同様に、編成中のキャラを持つ職を先に出す。
- 装備詳細から強化画面を開くボタンは「強化」と呼ぶ。中身が強化・売却なのに「評価」では何ができるのか伝わらない。
- 倉庫は「装備」「道具」「素材」「調合」の4区画に分ける。素材は結晶・核の全段階と全固有素材を、ゼロ個も含めた高密度グリッドで一度に見せる。交換・売却と入手先一覧は折り畳み、所持数の確認をスクロールの先へ追いやらない。売却と分解は同じ装備一覧の選択モードとして、絞込・並替とともに1段の操作列へ置く。選択モードでは開始ボタンを低レア一括選択へ差し替え、終了は固定確定ドックへ集約する。
- 装備の枠は高さを固定する。`min-height` にすると中身の量で段ごとに背が変わり、装備している段と空の段で大きさが揃わない。日常の装備一覧は高さ66pxとし、部位・更新可否・アイコン・品名・深度を2行に収める。**全16ステータスは装備を判断する情報なので装備タブに残す。能力タブへ移さない。** 2列の高密度表にして、縦長のカード列へ戻さない。
- 装備タブのキャラクター枠は拠点の編成枠と同じ見た目にする。同じ「誰で潜るか」を画面ごとに別の形で見せない。
- 「おすすめ」に出すのは **戦闘力が最も高くなる1件だけ**。同値が複数あるときだけ全部出す。候補を上位3件まで並べていたころは、どれを押せばいいのかを結局こちらで見比べる必要があり、おすすめの用を成していなかった。
- 戦闘力は職業と能力振りを込みで評価する。魔力0の戦士に深度300の伝説の杖を持たせれば、深度20の並の剣より低く出る。これは正しい挙動なので、検査で「深いほど強い」を確かめるときは主ステータスを揃えて比べる。
- 持ち込み枠は2列の横長行にし、アイコン・品名・所持数を分離する。品名へ省略記号を使わず、最低でも品名全体を読める幅を確保する。技名と消費MPは「ひとかたまり」として中央に置く（名前だけを中心へ絶対配置して消費を下にぶら下げると、組の重心が下へ傾いて見える）。
- 編成の枠に入れるのは アイコン / 名前 / レベル / 枠色（等級）/ 職業印 / 左上の番手だけにする。番手だけの独立した帯は置かず、4枠を高さ66pxの1段に収める。
- 消耗品は輪郭で判別できる絵と色を持たせる。漢字1文字や絵文字では、並べたときに見分けが付かない。
- **全滅したら必ず拠点へ戻す。** 死んでも同じ場所から再開する仕組み（`resumeFloorAfterDeath`）は
  **次の番手がいる交代のときだけ**に使う。次がいない全滅にも適用すると、最後の1人が倒れても
  HP55%の復活を繰り返してダンジョンから永久に出られない。「ここで力尽きる」も
  `partyIndex` を末尾へ送って同じ経路を通るので、同時に出られなくなる。
- **この不具合は計測も壊す。** ボットが死ななくなるため死亡率が実際より低く出て、
  50%死亡深度が 38 相当から 107 へ、総合力2倍の伸びが +14層 から +2層 へ化けた。
  消耗品の寄与も +11.5pt が -2.1pt に反転した。
  **「難易度が急に緩んだ」ように見えたら、まず死亡が死亡として数えられているかを疑う。**
- 番手が倒れて交代したら、技ボタンの表示を新しいキャラクターの中身へ描き直す。表示は `beginRun` でしか書いていなかったため、交代しても前のキャラクターの技名が残り、押すと別の技（固有技を差していた枠は共通技へ差し戻ったもの）が出ていた。
- レベル・経験値・能力値・装備はキャラクターごとに別で持つ（`characterStates[key] = {base, gear}`）。倉庫は共有し、他キャラクターが装備中の品も一覧に残して `E` と所有者を示す。選ぶと「誰が装備しているか」を明示して確認し、承認後だけ元の装備枠から外して現在のキャラクターへ移す。各装備は永続UIDで追跡し、倉庫と装備枠の二重登録や移管時の消失を防ぐ。メインの能力を他のキャラクターへ反映する仕組みは無い。
- そのため管理者モードのレベル設定は「操作中の1人」と「所持している全員」の両方を用意する。1人だけ上げても、交代した2人目以降がLv1のままで検証にならない。
- 消耗品と素材の枠の色は等級から作る（絵の色は系統）。枠を固定色にすると、緑や青のアイテムが赤い枠に入って中身と食い違う。枠を系統色にすると、同じ系統の1段目と3段目が同じ見た目になる。
- 装備ガチャはフィールドのドロップ表とは別のレア度表を持つ。ドロップ表の「最低レア度」を乱数で決める作りにすると、その乱数の分布がそのまま排出率になる（`ri(1,4)` を最低レア度に使っており、4回に1回が伝説になっていた）。伝説はキャラクターのSSRと同程度に置く。
- 技の一覧は固有技を先頭に置く。共通プールの後ろに並べると深部の技に埋もれて存在に気付けない。
- 回復薬は潜行中だけ持ち込み上限より多く持てる（`HEAL_RUN_CAP`）。拾える上限を持ち込み上限と同じにすると、満載で入った瞬間に道中の回復薬が一切拾えなくなる。
- 調合は所持素材・作れる個数・消費内訳を先に見せ、個数を選んでから確認する。何がいくつ減るのか分からないまま「作る」だけを並べない。まとめ調合は ×1/×5/×10/最大 から選ぶ。作れないときは**足りない材料を名指しする**（「素材不足」だけでは何を狩ればよいか分からない）。
- 調合の一覧は系統ごとに見出しを立て、1段目→3段目の順に並べる。段が上がるほど強く作りにくいことが、並び順そのものから読めるようにする。
- ゴールドで買える日替わり素材枠を置く（毎日ログインする動機）。回数は日でしか回復させず、まとめ買いで先取りできないようにする。核は対象にせず結晶のみとする。
- 倉庫の記号の凡例は「見かた」からポップアップで開く。一度読めば済むものを本文へ常時出すと、毎回グリッドの表示数を減らすためである。素材の所持数は1行に畳む（「なし」を言うのにカード1枚は要らない）。
- 死亡後の帰還ボタンは自動で戻るまでの残り秒数と、押せばすぐ戻れることの両方を書く。「拠点へ戻る（10秒）」だけだと10秒待たされるように読める。
- 装備枠に出す名前は品目名（バトルアックス等）だけを1行に収め、溢れたら「…」で切る。接頭辞込みの正式名は枠に入りきらず「バトルアック／ス」と語尾が落ちる。正式名は詳細で見せる。
- レア度は倉庫でも装備タブでも同じ「枠の色」で示す。同じ持ち物なのに画面ごとに見分け方が変わってはいけない。
- 技は3枠に職ごとの技プール（各8種）から選んで差す。解放条件は最大到達深度だけにする。ジェムや課金で強い技を解放できるようにすると、収支が金で買えることになり、課金アイテムのチート対策とも矛盾する。
- 技の種別は cleave / dash / slam / ball / nova / chain / pierce / cry。同じ種別でも消費・再使用・射程・範囲を変えて、連射型と一撃型、機動型と据え置き型が選べるようにする。
- 貫通弾（pierce）は当てた相手を弾ごとに覚えて二度打ちしない。上限体数に達したら消える。
- 自己強化（cry）は祭壇とは別の時計（buffT / buffAtk / buffDr）を使う。祭壇の時計を流用すると、効果時間が互いに上書きされる。効果中はHUDのバフ欄に残り秒数と倍率を出す（切れ目が見えないと置き直す判断ができない）。
- 技枠は常にどれか1つが選択された状態にする。未選択だと「一覧を押すとどの枠へ入るのか」が画面から読み取れない。
- 未解放や不明なIDがセーブに混じっても、装備中の3枠は必ず埋め、同じ技を2枠へ並べない。空き枠や重複枠はそのまま死に枠になる。
- ガチャは単発と10連を並べ、提供割合をその場から開けるようにする。10連の消費は単発10回とちょうど同額にし、割引は付けない（単発と10連を往復して得をする抜け道になる）。10連の利点はレア度の下限保証だけに限る。
- 商店はガチャ、ジェム購入、ゴールド商品のサブ画面、設定は表示項目と管理機能を持つ。購入系は説明と価格とボタンを1枚のカードにまとめ、どのボタンがどの商品のものか一目で分かるようにする。
- 強調表示（金色）は択一の選択肢で「今選ばれているもの」にだけ使う。ON/OFF の切り替えに使うと、既定でONの項目が多い設定画面が金一色になり選択状態が読めなくなる。切り替えは行末のON/OFFチップで示す。
- 別々の設定を同じ見た目で連続させない。操作モードと自動時の戦い方はそれぞれ見出しと一行説明を持つ。
- ダンジョンHUDはHP/MP/XP、深度、今回の獲得金、DPS、時間、ミニマップを表示する。潜行中の金額は所持総額ではなく今回の獲得額を出す。
- **HPは上のバーだけ**にする。技のそばにもう一本置いていたが、同じ数字が画面に2つある状態で、片方を読めば足りる。
- **拾った物の一覧は戦闘中に出さない。** HP/MPのすぐ下で数字が増減しても、戦っている間にそれでできることは何も無く、盤面から目を離させるだけ。同じ内容（ゴールド・未鑑定装備・素材・道具）は一時停止の「戦利品」に出る。
- ミニマップは **入った部屋から順に埋まる**。部屋は足を踏み入れた時点で丸ごと現れ、通路は歩いたぶんだけ細く残る（`CFG.MM_SEE_R`）。半径6の円を常に開けていたころは、部屋へ入る前から先の形が読めて、踏み込む前に通るかどうかを決められた。階段と帰還口の印も、その場所を見つけてから出す。
- ミニマップは**押すと大きく開く**（一辺88px → 約4倍）。小さいままでは通路の分岐が潰れて、どちらへ進んだのか読めない。**時間は止めない** — 止めると「地図を開いてから考える」のが常に最善手になり、盤面で判断させる意味が無くなる。大きさは下端が右の道具列の上で止まるよう詰め、開いている間も技と攻撃に手が届くようにする。
- 階段・帰還口への**矢印は出さない**（`CFG.GUIDE_ARROWS`）。行き先を常に指されると探索する意味が薄れる。戻したくなったらこの定数を `true` にするだけでよい。
- 回復薬の落ちている場所は、床の輪・光の柱・瓶の形・十字を重ねて遠目でも読めるようにし、ミニマップにも出す。直径8pxの赤い点では暗い床と血糊に紛れて拾い逃がす。最弱回復薬を持ち込んでいない潜行では生成せず、持ち込んでいても回復枠が満杯なら薄く描く。取りに行かせて無駄足を踏ませない。
- 操作系は縦持ちの親指基準で置く。右下に通常攻撃、その周りに3スキルを弧状（互いに最低2px空ける）、右端に持ち込みアイテムの縦一列、その最上段に操作モードの切替。移動スティックは左半分の不可視ゾーン。使用頻度の高いものほど親指に近い側へ置く。
- アイテムは持ち込み枠ぶんのボタンを常時並べ、1タップで使う。長押しで扇を開く方式は、押しっぱなしが要るうえ選択中の中身が見えないため使わない。
- 操作モード（手動／片手／オート）は戦闘画面から切り替えられること。未到達の深度ではオートを選ばせない。
- **任せたぶんだけ与ダメージが下がる。** 手動 ＞ 片手（`CFG.ONEHAND_DMG` 33%減）＞ オート（`CFG.AUTO_DMG` 50%減）。片手は狙いを、オートは狙いと移動の両方を自動に任せている。丁寧に動かす側が損をするなら、手で操作する意味が無くなる。減っていることは設定・説明・切替時の表示すべてに書く（隠れた減衰にしない）。実測の50%死亡深度は 手動55 / 片手33 / オート28。
- 切替ボタンは **手動 → 片手 → オート の3つを必ず一巡する**。未到達の深度でオートを黙って飛ばしていたころは、最深で潜っている間ずっと2択にしか見えず「オートが無い」と読めた。飛ばすのはやめ、代わりに切り替えた時に「未到達の深度です」と出す。自力で越えてほしいという意図は残しつつ、選べないことを画面から隠さない。
- **操作キーの左右は、移動キー・技・道具をそれぞれ独立に入れ替えられる。** 利き手も持ち方も人によるので、3つまとめてではなく別々に選ばせる。反転は `left`/`right` の入れ替えだけで行う（`transform:scaleX(-1)` だと中の文字まで鏡文字になる）。設定は起動時に `applyMirror()` で body の class へ写す。
- 右端の縦一列は、**いちばん下が操作モードの切替**で、その上に持ち込み枠ぶんの道具を並べる。切替の位置は持ち込み数で動かさない。盤面を見たまま指で探せることが要る。
- 道具の枠は**空きでも出す**。持ち込んでいない時だけ列が縮むと、同じ道具が毎回ちがう高さに来る。
- 丸いボタンは幅と高さを両方とも 44px で指定する。40px で作ると全体規則の `min-height:44px` に縦だけ引き伸ばされ、`border-radius:50%` が楕円になる。
- 技名は円の内側の垂直中央に置く。中央から外れると、その高さでの弦が狭くなり `overflow:hidden` の丸い切り抜きで文字が削れる。文字は円に内接する正方形（一辺 r√2）に収まる大きさにする。
- 技ボタンの表示切替は名前ごと入った外枠に対して行い、`display` を技ボタン自身へ直接書かない（`.sk` の `display:flex` を打ち消してコストの中央寄せが壊れる）。
- 自分の位置は足元の輪と向きの三角で常に示す。自機と敵は同じ塗り分けの輪郭で描くため、印が無いと敵が多い画面で自分を見失う。
- 記号には必ず画面内に意味を書く。倉庫グリッドの▲（装備中より強い）・E（装備中）・数字（深度）・枠色（レア度）は凡例を出す。装備タブでは倉庫に上位品がある部位へ▲を出し、帰還画面の戦利品にも装備中より強いかを表示する。
- ボスのHPバーは囲いを付けて自分のHP/MP/XPバーと別物に見せ、ミニマップの左側の幅に収める。囲いが無いと、上端に赤い横棒が2本並ぶだけになって取り違える。
- 道具のボタンは技より一段おとなしい配色にする。同じ濃さで並べると主役（技・攻撃）が埋もれ、視線も盤面から右端へ引っ張られる。
- 同じ機能を画面ごとに別の名前で呼ばない（操作モードは戦闘画面でも設定画面でも「手動／片手／オート」）。
- 一時停止画面は「戦利品」「装備・能力」「設定」の3タブと再開/断念操作を持つ。背景は不透明に塗らず盤面を暗く透かす（止めただけであって別画面へ移ったわけではない）。断念は再開の隣に同じ大きさで置かない。
- ポップアップはレベルアップ選択、装備詳細/強化/編成、確認、宝箱解錠、通知を扱う。

## データ引き継ぎ
- セーブは localStorage にしか無く、これは**出所（URL）ごとに別物**なので、URLが変われば中身は引き継げない。持ち出せる形を用意することが唯一の対策になる。「更新のたびに1から」を放置しない。
- 形式は `DESCENT1:G:<base64>`（`G`=gzip圧縮 / `P`=無圧縮）。圧縮はブラウザ標準の `CompressionStream` だけを使い、外部ライブラリは入れない。実測で 41,000字 → 10,000字 程度まで縮む。
- 書き出しは **ファイル保存**と**コード表示**の両方を出す。セーブは倉庫が増えると90KBを超えるので、貼り付けだけに頼らせない。読み込みも**ファイル**と**貼り付け**の両方から入れる。
- 読み込む前に、**入ってくる内容と、いま入っている内容の両方**を出して確認させる（深度 / Lv / 所持金 / ジェム / 仲間の数 / 倉庫の数）。上書きしてから気付かせない。
- 直前のデータは1つだけ `descent_v5_before_restore` に残し、「復元する前のデータに戻す」で戻せるようにする。読み込むコードを間違えても取り返しがつくようにする。
- 受け取ったコードは必ず検査する。印が違う・途中で切れている・別のゲームのJSONは、**日本語で理由を言って**断る。展開の失敗はブラウザの英語の例外がそのまま出るので、こちらの文言に置き換える。あわせて `CompressionStream` の writable 側の失敗も受けておく（放置するとページ全体の未処理エラーとして表に出る）。
- 貼り付けに混じる改行・空白は取り除いてから読む。

## 状態（S）の主要フィールドとセーブ形式
- `S` は画面/職業/プレイヤー、現在深度と最深度、敵・弾・描画物、階段/門/ボスを保持する。
- `bag` は未帰還品、`stash` は倉庫、`gear` は現キャラ装備、`mats` は素材の種類/階梯別カウンタ。
- `base` はレベル、XP、未使用能力点、6基本能力、`p` はそこから導出した戦闘中能力とHP/MP。
- `characterStates` はキャラクター別の `base`/`gear`、`formation` は出撃順を保存する。
- ラン時間/獲得金/開始階/戦闘ログ、タブ、設定、チュートリアル、管理者状態も `S` にある。
- 保存先は localStorage の `descent_v5`、JSONオブジェクトとして永続フィールドだけを書き出す。
- 敵、弾、マップ、現在ランの一時描画物などは保存せず、潜行開始時に再生成する。
- ロード時は旧リング名、廃止ベルト、旧主能力、旧装備名、旧能力スキーマを移行する。
- 欠けたフィールドには既定値を補い、職業/キャラクター別状態と現装備を再接続する。

## 戦闘（通常攻撃・スキル・状態異常・敵AI・ボス）
- 通常攻撃は職業の物理/特殊攻撃、射程、攻撃速度を使い、基礎倍率は0.68。通常攻撃を戦闘の土台として成立させ、装備攻撃力が増えても技との比率が変わらないよう、攻撃技は同じ基礎式に通常攻撃比の `mul` を掛ける。薙ぎ払い1.3倍・突進斬り1.5倍・大地砕き1.7倍とする。
- 戦士は薙ぎ払い/突進斬り/大地砕き、魔術師は火球/氷結新星/連鎖雷撃をMPで使う。
- クリティカル、回避、防御/軽減、吸収、ノックバック、クールダウンとMP回復がある。
- 燃焼/毒は最大HP割合の継続ダメージ、凍結/麻痺は行動阻害として敵味方に付く。
- 通常敵は追跡、跳躍、突進、距離維持射撃、自爆など種類固有AIを持つ。
- エリートは氷結、業火、守護、分裂、迅雷、再生、爆散の特性を一つ得る。
- ボスは属性ごとに2体、計10体。5深度ごとに属性が一巡し、一巡目は各属性の1体目、二巡目は2体目が出る（50深度で全10体が一巡）。各ボスは固有技＋狙い撃ち＋衝撃波の3技を持つ。技後は深度1で約1.35秒、深度100で約0.32秒の隙を作る。
- ボスは体格と数値だけでなく挙動が別物であること。同じ属性の2体も別の攻略を要求する。実装済みの挙動は charger（突進して跡を燃やす）／barrage（円状の弾幕）／circler（周回して突っ込む）／expand（広がる氷の輪）／summoner（据え置きで増援）／zoner（毒沼を撒いて距離を取る）／blinker（瞬間移動して光線）／guardian（正面を通さない）／vanisher（消えて背後から）／reflector（配下がいる間硬く、反射する）。
- 出現時に一度だけ、その相手の攻略の要点を出す。初見で挙動の意図が伝わらないと総当たりになる。
- ボスの突進は1回の突進につき1度しか当てない。重なっている間ずっと判定を出すと、0.45秒で27回殴られる。
- ボスはHP半分で激昂し、速度と攻撃間隔が強化され、撃破で次深度を解放する。
- 敵の種類は深く潜るほど増やす。序盤（深度1〜10）は素直に追ってくる弱い3種だけにし、重い型（巨躯・爆ぜ手）や搦め手（盾番・瞬き・分かれ身）は深部へ置く。最後の1種は深度60まで引っ張り、深部でも「新しい敵が出る」感触を残す。
- 敵の解放深度を動かすと `check-balance` の素手の帯が動く（装備なしの到達は、そこにどんな敵が出るかでほぼ決まる）。序盤を薄くした分は素手が深くまで行くので、帯の方を実測に合わせて直す。
- 通常敵は「まっすぐ追ってくる」型だけにしない。weave（蛇行）／orbit（周回）／phase（横へ跳ぶ）／front（正面を半減、向き直りが遅い）／drain（触れて回復）／splits（倒すと分裂）を用意し、深いほど出やすくする。
- 深度が上がるほど当てにくい動きにする。速度だけを上げると回避不能な事故が増えるので、蛇行の振れ幅・回り込みの速さ・横跳びの頻度・進路のずらしを深度で伸ばす（深度8で0、深度100で約1）。
- `ET` に挙動の印を足したら `spawnE` の写し取りにも足す。写し忘れると表には書いてあるのに効かない。
- 新しい敵の体力・攻撃は既存の同格に合わせ、手強さは動きで出す。数値の壁として積むと、その解放深度の帯だけ到達深度が落ちる。実際、新型6種を体力・出現比率とも盛った時点で標準プロファイルの50%死亡深度が 55〜70 から 34 まで落ち、同格へ揃え直して 63 に戻した。
- 敵を追加・変更したら `npm run check`（`check-balance`）で3プロファイルすべてが目標帯に入ることを確認する。中盤（標準・目標38〜55）が最も動きやすい。
- 敵編成を変えると `check-elements` の判定値も動く。属性検査は「到達深度」を材料にしており、到達は45秒の床掃除が間に合うかで決まるため、倒すのに時間がかかる敵を増やすと火力差（＝属性差）が結果に出にくくなる。閾値は敵編成に合わせた調整値として扱い、動かしたときは理由を残す。
## 深部の圧力（烙印と回避不能弾）
- 敵の索敵距離は既定11。ここが一律だと、走って離れ続けるだけでどの敵も起きず、深部でも「時間をかければ無傷で勝てる」状態になる。遠くから撃つ型は個別に長い索敵距離を持つ。
- **烙印**（深度64から）は「移動では避けられない弾」を撃つ。速度5.0（プレイヤーは3.5）で6秒のあいだ曲がり続けるため、走って距離を取る戦法だけを潰す。索敵19・射程15で、逃げる相手にも足ではなく射程で届く。
- 避けられないのは**移動に対してだけ**。`hurtP` を通るので**回避率（素早さ）では避けられる**し、壁は弾を止める。地形を使う立ち回りは残す。
- 烙印の数は深度に応じて増やす（64深度で1体、18深度ごとに+1、上限5体）。抽選任せだと深部でも0〜1体しか出ず抑止にならなかった。湧き上限に達したフロアでは並の敵と**入れ替える**（総数を増やさないので掃除にかかる時間は変わらず、圧力だけが増える）。
- 実測（2026-08-16）: 厳選プロファイルの50%死亡深度が103→100、総合力2倍の到達深度増分が+12→+17。深部で装備の差が出るようになった。

## 画面の作りの検査（`npm run check:ui`）
毎回同じ種類の指摘が出ていたので、人が気付く前に落とす検査を置く。実機と同じ 390x844 で、10画面とポップアップ4種を実際のDOMで測る。

1. **同じ並びの枠は同じ大きさ** — 横1行に収まっている兄弟の高さ・幅の差が2pxを超えたら落とす。
2. **あふれているのにスクロールできない** — `scrollHeight > clientHeight` なのに `overflow-y` が `auto|scroll` でなければ落とす。ポップアップも同様に見る。
3. **演出と状態が残らない** — 潜行→被弾→帰還を通し、被弾の赤・戦闘用HP・敵・弾・演出・粒子・開いたままの画面が残っていたら落とす。
4. **文字が枠からはみ出す／切られる** — `scrollWidth > clientWidth`（省略指定なし）と、`overflow:hidden` の親からの上下はみ出しを見る。
5. **フォントと色** — 指定漏れで serif に落ちていないか。文字と地のコントラスト比が2.2未満なら落とす。半透明の地は親に合成してから測る（透過を無視すると「金文字に12%の金地」を同色と誤判定する）。
6. **強調ボタンが埋もれていない** — `.gold` `.pri` `.go` が通常ボタンと同じ面色になっていたら落とす。一括の面指定で「潜る」の赤が消えたことがある。
7. **日常画面に不要な縦スクロールがない** — 390x844で拠点、装備一覧、能力割り振り、ガチャ、表示設定の `scrollHeight - clientHeight` が4pxを超えたら落とす。装備詳細や調合のように内容量そのものが多い画面だけを対象外とする。
8. **コンパクト化してもタップ領域を削らない** — 拠点のヘルプ、階層表示、出撃、任務/記録の短縮導線は実測44px以上を要求する。

Playwright を使うので `npm run check` には入れない（Codex環境で入らないため）。`check:layout` `check:playable` と同じ扱い。

Playwright が無い環境でも、`npm run check:ui-structure` はゲーム本体を実行してDOM構造を検査する。装備タブ内の全ステータス、能力タブ内の6割り振り、持ち込みの完全な品名、倉庫操作のSVG、ミッション/設定のカテゴリ名が欠けたら失敗し、`npm run check` にも含める。

`npm run check:inventory-safety` は、7部位（手袋を含む）の帰還抽出・保存再読込、装備UID、保護、他キャラクターからの確認付き移管、編成離脱時の全解除、最弱回復薬の条件付きドロップ、100Fの25%上限、技倍率2倍上限、開始階層の自由入力をゲーム本体上で検査し、`npm run check` にも含める。

## リリース用ビジュアルシステム（Obsidian / Ember）

- 暗い世界観は維持するが、背景と本文を同じ紫黒へ沈めない。面は青みのある黒、本文は温かい白、補助文は青灰色に分ける。強調色の役割は、**金＝現在の選択・価値、青＝情報・フォーカス、水緑＝成功・ON、赤＝主操作・危険**に固定する。設定のONをすべて金にすると選択状態と区別できないため、ONチップは水緑にする。
- 基準色のコントラスト実測は、本文17.26:1、補助文9.11:1、弱い補助文5.80:1、非選択タブ5.37:1。グラデーション面では `check:ui` が実DOM上の合成後の色を別途検査する。
- 読むだけのカード、押せるカード、主要操作の3段階を面の明るさ・枠・影で分ける。すべてを同じ紫色の矩形にすると、どこから操作を始めるか判断できないためである。
- 下部の主要5タブは線画アイコンと文字を併記し、選択中だけ金の上辺と薄い面を出す。アイコンだけにはせず、日本語ラベルを残す。
- 拠点本文はスマートフォンで全幅、広い画面では内容幅760pxまでに抑えて中央へ置く。4枠や能力値が画面いっぱいに引き伸ばされて文字が散るのを防ぐ。
- 初回のクラス選択は、職業姿・前衛／後衛・HP／MP／射程・初期技を1枚にまとめる。数値だけのカードより、選んだ後の操作感を比較して決められることを優先する。
- `tapEl` で結ぶ操作面には `role="button"` とキーボードフォーカスを付け、Enter／Spaceでも実行できるようにする。フォーカスは情報色の輪郭で表示する。
- ダンジョンは照明範囲を変えず、暗幕だけを `DARKNESS .86 → .80` に弱め、床・壁・敵の中間色を一段上げる。探索範囲や敵の検知条件は変えず、端末の黒つぶれで地形と自機が消える問題だけを軽減する。
- 倉庫の選択処分ドックは「合計／実行／キャンセル」の1行3列とする。報酬文を短くして320px幅でも同じ行に収め、一覧を覆う高さを増やさない。

## 日常画面のコンパクトシェル

- リリース品質は装飾量ではなく、**主操作までの距離・情報の重複・視線の順序**で判定する。読むだけの文章まで枠で囲わず、区切り線、左辺のアクセント、菱形の装飾を使って世界観を出す。画面全体を同じ大カードで縦積みしない。
- 拠点は「次の行動 → 編成 → 持ち込み → 任務/記録」を本文1画面に収め、出撃は固定バーに分離する。編成と持ち込みの規則は常駐文ではなく44pxの `?` から開く。
- 装備一覧は上部プロフィールに戦闘力を一度だけ見せ、本文は7部位＋8枠目の「おすすめ」、全16ステータスで構成する。独立した装備診断行は置かない。能力タブは「残りポイント → 2列×3段の割り振り → 確定/振り直し」だけにし、ステータス表を置かない。
- 倉庫の装備グリッドは360px以上で6列、狭い端末だけ5列とする。操作列を1段に固定し、選択時だけ確定ドックぶんの下余白を足す。通常時に固定バーの空きを残さない。
- 倉庫の絞込・並替・売却・分解・見かたは、Unicode文字や絵文字をアイコン代わりにせず、装備アイコンと同じ24px座標・2px線幅のSVGで統一する。
- ガチャは絵の領域と名称・保証・提供割合・単発/10連を1枚の横長ポスターへまとめる。長い規則は提供割合へ降ろし、カード本文は1行で比較できる要点にする。
- 設定は「表示 / 操作 / データ / その他」の4カテゴリを切り替え、1カテゴリだけ表示する。機能は削らず、目的の設定までスクロールで探す操作をなくす。
- 小さい枠にしたことを理由に文字や当たり判定を小さくしない。読ませる文字は11px以上、主要操作は44px以上を維持し、見た目の装飾面だけを薄く・短くする。

## 画面設計の下限（実測で守る）
- **文字は11px以上**。7〜10pxは実機で潰れて読めない。装備枠で7pxを使っていた。`check:ui` が全画面を走査して落とす。
- **印は角に絶対配置しない**。枠の上段に帯を作り、左右に振り分ける。角に置くと印が増えたときに必ず重なる（更新可能の▲と分解選択の「分」が同じ左上に出ていた）。`check:ui` が絶対配置どうしの重なりと、枠外へのはみ出しを見る。
- **区画のタブと確定バーは固定**。タブが流れると、スクロールした先で切り替えるのに毎回一番上まで戻ることになる。確定バーは `position:sticky` ではなく下のタブ帯の真上に `fixed` で置く（sticky だと一覧の続きがバーの下から覗いて、隠れているのかスクロールできるのか分からない）。
- **選択中の色はレア度の色と衝突させない**。選択の縁を金にしていたため、秀逸の枠と見分けが付かなかった。水色にする。
- **個数は押してから選ぶ**。枠ごとに ×1 ×5 ×10 を並べると、種類が増えるほどボタンだけで画面が埋まる。自由入力・−＋・最大の3つを持つ共通の画面（`askQuantity`）へ集約する。
- **長押しは加速させる**。一定速度のままだと、残りポイントが増えたときに押し続ける時間だけが延びる。数値そのものも押して直接入力できるようにする。
- **同じ一覧を2つの入口から開かない**。分解は売却と同じ「装備を選んで処分する」操作なので、単独タブではなく装備区画の中に置く。
- 装備枠には**部位・品名・深度・強化値・更新できるかどうか**を出す。品名は2行まで許す（1行に収めようとすると「ウォーハン…」と切れて読めない）。
- 円形のボタンに入る文字は**内接正方形（直径÷√2）**に収まること。文字を小さくするのではなく円を広げて解決する。


- 拠点の**押せる物は面で分かるようにする**。地(`--panel`)より明るい `--press` を与え、押した瞬間に沈ませる。読むだけのカードは面を持たない。暗さはこのゲームの個性なので全体は明るくしない。**強調色を持つボタン（`.gold` `.pri` `.go` `.no`）は上書きしない** — 一括指定で「潜る」の赤が消える。
- キャラクターは「●」ではなく**職業が分かる姿**（`ch_warrior` / `ch_mage`）を描く。立ち絵が無くても、輪郭・個人色・等級枠の3つで見分けが付く。
- 戦利品は1枚ずつ順に出す。**演出の終わった状態を既定値にして**（`backwards` と `opacity:1`）、途中で止まっても消えたままにならないようにする。光らせるのは1回だけ（無限に光らせると画面に残り続ける）。
- 潜行が終わったら `clearRunVisuals()` で戦闘専用の表示と場を必ず片付ける。`updHUD` は潜行中しか回らないので、戦闘HUDを消す責任をそちらに持たせると拠点へ戻っても出たままになる。
- **添字で回すループは、途中で配列が空になる前提で書く**。`hurtP` → `endRun` → `clearRunVisuals` が弾の更新ループの内側から走るため、`S.bullets[i]` が undefined になり得る。


- 押せる要素の最小の辺は **44px**。実測で29pxの物が各画面に8〜13個あり、指の腹（約45px）より小さかった。枠を大きくしてよい所は `min-height` で確保し、大きくすると画面が間延びする所（頭の名前・通貨・?印・−＋・注釈のリンク）は透明な擬似要素で当たり判定だけ広げる。`overflow:hidden` が要る枠は擬似要素が切れるので、上下の padding を負の margin で打ち消して枠だけを大きくする。
- 何が押せるかは class 名から当てにいかない。`tapEl` / `repeatBtn` が `data-tap` を残し、`check:playable` はそれと擬似要素の当たり判定を見る。class 名で推測していたころは、押せない飾りの枠を数える一方で、実際に押せる小さな要素（15pxの「提供割合を見る」、16pxの名前、27pxの−＋）を丸ごと見逃していた。
- 文字の下限は12px。所持数やレベルなど「読む必要のある情報」に9〜11pxを使わない。
- **戦闘力**（`combatPower`）を全画面に常駐させる。能力値16項目を見比べないと強くなったか分からない状態が、装備・継承・強化・編成すべての判断を重くしていた。期待火力と実効耐久の相乗平均にして、片方だけ盛っても頭打ちにする。
- 装備枠を押したら、その画面で候補を出して**押した瞬間に装備する**。以前は「枠→装備変更→一覧→選ぶ→決定」で5タップかかっていた。細かく見たい人だけ「すべての候補から選ぶ」へ降りる。
- 装備の比較は**変化のある項目だけを符号付き**で出す。表示名で合算する（`armor` と `dr` はどちらも「防御力」で、別行に出ると同じ名前が符号違いで2つ並ぶ）。
- 拠点の先頭に「次にできること」を1つだけ出す。判定は `pendingCounts()`（受取可能な任務／いまより強い装備がある部位／未確認の戦利品）で、タブのバッジと同じ根拠を使う。
- 常駐の説明文は初回だけ出して畳む（`hint()`）。慣れたあとも画面を占有させない。
- 戦闘中のHPは**技ボタンの近く**に置く。右下を見ているのに対角の左上に細い線があるだけだった。被弾は画面の縁に赤を残す（暗い画面ではフラッシュだけでは気付けない）。持ち込んでいない道具枠は戦闘中に出さない。

## 継承（装備の階層引き上げ）
- 深く潜るたび、良いオプションが付いた装備が階層差だけで置き去りになる。拾い直しを強いると「気に入った1本を育てる」楽しみが消えるので、お気に入りの1本を今の階層へ引き上げられるようにする。
- 素材は**同じレア度の装備を3個**と、課金枠の**継承の印**1個。伝説を伸ばすには伝説を差し出すことになるので、価値の交換として釣り合う。
- 引き上げ先は**投入した素材のうち最も浅い階層**。素材より上には行けないので、深層の装備を配らないかぎりインフレしない。
- オプションの構成・品質・固有効果・名前はそのまま、値だけ新しい階層で引き直す。主能力は生成時と同じ式の中央値にする（引き上げのたびに引き直せる「振り直し」にしないため）。
- 装備中の品、保護中の品、対象より浅い階層の品は素材に選べない。消費は成立が確定してから行い、片方だけ減らさない。

## 伝説専用効果（固有効果）の重ねがけ
- 同じ固有効果を複数の装備で持ったとき、以前は2個目以降を捨てていた（`!pw.includes` で弾いていた）ため、伝説を2個そろえても片方が完全に無駄になっていた。個数を数えて効果量に反映する。
- 倍率は `pwStack(n) = 2 - 0.5^(n-1)`。1個=1.00、2個=1.50、3個=1.75、4個=1.875…と**増分を半分ずつ落とし、何個重ねても2.00倍を超えない**。同じ効果を集めるだけで青天井にならないよう、「単純に2倍」ではなく「効果上昇」に留めるための形。
- 適用先は各効果の代表的な数値ひとつに絞る（爆風の威力、衝撃波の威力、回復量、CD短縮量、ドロップ倍率、背水の上限、連鎖の威力、不動の1段あたり軽減、分身の伸び、深淵の泉の倍率）。発動頻度は変えない。
- **別々の固有効果はこれまでどおり全部が等倍で乗る**。重ねがけ倍率がかかるのは同じ効果どうしのときだけ。
- 能力画面に「×3 → 効果 1.75倍」と実効倍率を出し、規則の説明は見出しの下に1回だけ置く。装備の詳細でも、同じ効果を既に着けている場合は「これを足すと効果 N倍」を出して、重ねる価値をその場で判断できるようにする。

## 職業
- 遠距離職の照準扇（`aim`）は近接と別に持つ。以前は遠距離を .55 固定にしていたため、射程6.2まで届くのに少し横へずれただけで素通りしていた（実測: 狙いを1.0radずらすと威力が2割落ちた）。1.15にすると狙いのずれで威力が落ちなくなる。
- 遠距離職の通常攻撃は2体まで貫通し、弱いノックバックを持つ。近接の通常攻撃が扇で複数に当たるのに対し、遠距離は単体しか殴れず、耐久（`defMul` .62）でも劣っていた。
- 弾のノックバックは近接を1とした係数（`kb`）で持つ。以前は弾速の2%（12×.02＝0.24）を渡しており、体感できる量ではなかった。

- 逃げ回る型・硬い型を湧きの多数派にしない。深部の潜行が「倒しきれるか」ではなく「時間内に掃除しきれるか」で決まると、火力も装備も消耗品も結果を変えられなくなる（実測で消耗品の到達深度差が +8 から 0 へ潰れた）。従来型を厚めに入れて新型は2割前後に保つ。
- `NEUTRAL_BASE`（無属性の基礎値倍率）は無属性ビルド専用の調整値ではない。属性ビルドも一部の部位に無属性を混ぜるため、ここを動かすと全ビルドの地力が動く。全体の強さを変えずに無属性だけを動かしたい場合は使えない。
- 伝説固有効果やラン中レベルアップ選択は攻撃、範囲、回復、軽減、ドロップを修飾する。

## 装備（スロット、レア度、オプション、合成）
- スロットは武器、兜、鎧、手袋、靴、指輪、首飾りの7枠（武器/防具には職業適性あり）。
- レア度は並、上質、希少、秀逸、伝説の5段階で、付与オプション数は0〜5。
- 主能力は部位基礎範囲×`ilvl^0.62`、不適性防具の主能力は60%になる。
- オプションは攻撃、HP、防御、会心、速度、吸収、短縮、運などから重複なしで抽選する。
- `derive()` の%系には安全弁の上限を置く。射程2.2倍、会心率100%、会心倍率6.0倍、攻撃速度2.6倍、移動速度2.0倍、発見率3.0倍、吸収3%、短縮50%。%オプションの抽選上限は深度に比例して伸びるため、上限が無いと深度1000で攻撃速度40倍・移動速度34倍に達し、当たり判定と移動が破綻する。
- ただし抽選上限そのものは未調整で、深度100の理論最大でも攻撃速度5.5倍・移動速度4.3倍に達する。%の伸びを深度で飽和させる案は、標準プロファイルの到達深度が55〜70から42へ落ちるため、実数オプション側の再調整とセットでなければ入れられない。（未決）
- 品質係数は0.75〜1.35で、表示上は高品質/低品質の印を付ける。
- 伝説には装備中だけ働く固有効果を一つ付け、名称とアイコンは部位/職業から生成する。伝説の名前は虹色グラデーション（`color:transparent`）で描くため、同じクラスを付けたアイコンには stroke を明示する。指定しないと `currentColor` が透明になり、一番うれしいドロップだけ絵が消える。
- 装備名は 接頭 → 修飾（「熊の」「不滅の」）→ 部位名 の順で組む。修飾語は後ろに名詞が来る形なので、部位名の後ろに付けると「サレット不滅の」と語尾が浮く。
- 合成は素材装備をXPとして消費する既存経路と、結晶で1段階上げる経路を併設する。
- 素材装備からXPを入れる場合も、実際に段階が上がるごとに対象階梯以上の結晶を消費する。
- 強化上限は `10 + floor(sqrt(ilvl))`（深度100で20、1000で41）で装備ごとに決まる。
- 主能力は強化1段階ごとに基礎値の7%を加算し、強化済み値への乗算（複利）はしない。
- 合成XPの次レベル必要量は装備深度の平方根で緩やかに増え、強化レベル自体による指数増加は行わない。深度60で87、深度1000で182。
- 「強化後予測」と必要素材の計算は、実際の合成処理と同じ必要量を使う。深度を落とした値（ilvl=1相当の60）で見積もると、予測が実際より多くの段階を表示し、必要素材も過大に数える。
- 強化素材は結晶と核のみで、階梯は `max(1, ceil(log2(ilvl/10+1)))` とする（深度1〜10は階梯1）。
- 上位階梯は1個を下位4個相当として代用できるが、下位から上位への変換はできない。
- 分解結晶は並1/上質2/希少5/秀逸12/伝説30個を基準に、生成深度の平方根スケールを掛ける。強化費は「深度1から目標深度まで順に降りる」潜行で累積するドロップ量に合わせた深度係数を掛け、深度10〜1000で完成まで20〜40潜行に保つ。
- 強化上限の後半1/3では結晶に加えて同階梯以上の核1個を段階ごとに消費する。
- 売却価格、合成費、素材XPは装備深度、レア度、強化段階から計算する。

## 装備属性・共鳴・敵属性
- 属性は装備だけが持ち、火・水・木・光・闇・無属性の6分類とする。キャラクター状態には属性を保存しない。属性導入前の装備はロード時に無属性へ移行する。
- 火→木→水→火を有利・不利の向きとし、光と闇は互いに有利、それ以外の光闇対面は中立とする。無属性は攻防とも常に1.0倍とする。
- どの属性にも強い相手と弱い相手を必ず持たせる。光と闇は互いに与ダメージも被ダメージも上がる高リスク高リターンとして扱い、被ダメージ判定を「相手に勝てるなら軽減」だけで決めない。対称な光闇を勝ち負け判定に通すと双方が軽減側に回り、光闇だけ不利帯を持たないビルドになる。
- 同属性装備3/5/7個で弱/中/強共鳴となり、通常攻撃とスキルがその属性になる。有利時の与ダメージは火水木が1.8/4.5/6.0倍、出現頻度の低い光闇が1.8/5.0/6.5倍と段階ごとに単調増加し、中立時1.0倍、不利時0.5倍とする。不利倍率は深度100以降、深度200の0.65倍へ線形に緩和する。被ダメージは有利な敵から0.85/0.75/0.70倍、不利な敵から1.15/1.25/1.30倍とし、有利側の軽減幅は不利側の増加幅の1.5倍を超えないこと。無属性装備は共鳴数に含めず、主能力と基礎オプションを1.15倍にする。
- 到達深度の差は「属性を帯に合わせて持ち替えたか」で付ける。属性を固定したまま8帯を潜ると有利帯と不利帯が相殺し、無属性を上回らない（無属性の主能力1.15倍ぶん、8層までは下振れてよい）。各帯の優勢属性に勝てる属性へ持ち替えたときだけ無属性より+5〜+15層深くまで到達でき、固定運用の平均も5層以上上回る。
- 光闇は8帯のうち1帯でしか対面が起きず、火水木のように不利帯を2つ抱えない。そのため固定運用の到達深度は火水木より高く出るのが正常で、上限は「無属性を上回らない」ことで縛る。火水木最高から8層以上沈むのも不可とし、希少属性が実用外にならないようにする。
- 検証は条件を緩和せず、実生成敵への実攻撃を用いる。5属性差±5、属性固定平均と無属性の差が+3〜−8層、帯に合わせた到達深度が無属性より+5〜+15かつ属性固定平均より+5以上、光闇が無属性を上回らない、属性帯時間比2.0以上、無属性帯間比1.2以下、通常敵は無属性ダメージ優位、弱点敵は5個共鳴が無属性の1.8倍以上、深度150不利帯で進行可能を必須とする。
- 通常敵は状態異常用 `res` と別に属性耐性 `eleRes` を持つ。ボスは属性耐性を持たず、5層ごとに火・水・木・光・闇を巡回して25層で一巡する。
- 通常フロアでは深度から決まる1属性を通常敵の約65%へ割り当てる。優勢属性は5層帯ごとに固定し、8帯周期で火・水・木・光・火・水・木・闇とする。開始深度の5層刻み選択を属性帯の選択に一致させ、周期を含む深度帯の出現割合を火・水・木は各20〜26%、光・闇は各11〜17%に保つ。
- 開始深度選択には開始フロアの優勢属性と次ボス属性を表示し、潜行中は深度表示の横に現在フロア（ボス階ではボス）の属性を表示する。装備アイコンは属性色で表示し、弱点ダメージは同色かつクリティカル相当の大きさ・ヒットストップで示す。

## 進行（XP曲線、階層スケーリング関数、ドロップ率）
- レベルに上限はなく、Lv100以降も通常のレベルアップを続け、レベルごとに能力点5を得て6基本能力へ任意配分する。
- 累積XPはLv1/10/20/30/40の既存アンカーを1.7乗補間し、Lv40〜100は `XP_MID_GROWTH`、Lv100以降は独立した `XP_HIGH_GROWTH` で外挿する。将来の高レベル緩和は後者だけを調整する。
- 深度100周回を1潜行197,540 XPと仮定し、Lv90は150〜250潜行、Lv100は350〜600潜行、Lv110は2,000〜4,000潜行を目安とする。レベルを深度の前提条件にはしない。
- 通常敵とボスのHP・攻撃は `ENEMY_ACCEL_START` 以降、共通の `ENEMY_ACCEL_GROWTH` で加速する。プレイヤー能力には上限や逓減を設けない。
- 核は4:00更新の日次獲得上限3個、保有上限16個とし、結晶・装備・XPおよび潜行回数は制限しない。ジェム購入の核は週6個までとする。
- キャラクターは等級（N/R/SR/SSR）を持ち、上ほど能力補正が強く固有技も強い。N は配布枠でガチャからは出さない。R 以上はガチャからのみ入手する。初期キャラクターと、チュートリアルの無料ガチャで渡す1体は N とする。
- キャラクターは全員が固有技を1つ持ち、その本人しか技欄に差せない。等級差の中身をここに置く。
- 技の編成はキャラクター単位で保存する。職で共有すると、キャラクターを替えた瞬間に技1が黙って別物へ変わる。旧セーブの職単位の設定は、その職の先頭キャラクターへ引き継ぐ。
- キャラクターガチャは等級を先に抽選し、その等級の中で未所持を優先する。10連は10回目に SR 以上を保証する。提供割合には等級ごとの確率と、その等級に誰がいるかを併記する。
- 管理者モードとデバッグモードには、検証用のジェム加算口を置く（無制限）。リリース時に両モードごと削除する。
- 管理者モードには「遊び方・仕様」を開くボタンを置く。テストプレイ中に仕様をその場で引くためのもので、数字は定義から組み立てて本文とずれないようにする。管理者モードごとリリース時に削除する。
- キャラクターは5凸を上限とし、1/3/5凸で基礎能力+6%/+12%/+20%、2/4凸で追加特性、5凸で特性1強化を得る。凸は同キャラの重複1体につき1段だけ進む。誰を重ねるかを入手結果と直結させ、汎用核の積み立てで任意キャラへ迂回できないようにするためである。5凸後の重複は、調合と装備強化に用途が残る核3個へ変換する。旧セーブの凸向け積立核は、獲得済み資産を失わせないため現在階梯の核へ全額払い戻す。
- 編成2〜4枠は所有・編成による属性支援枠として扱い、死亡時の順次交代は維持する。初心者配布の基準深度は `ENEMY_ACCEL_START` に追従し、他プレイヤーの進行は参照しない。
- 初心者ミッションは底上げ専用で、既に基準レベルを超えているプレイヤーのレベルを下げない。受け取りボタンは未受領のあいだ出続けるため、基準を追い越してから押される経路が常にある。レベルを下げてよいのは管理者モードだけ。
- 新規キャラクターの能力値は必ず `xpCurveV2` を立てて作る。立てないと読込時の旧XPカーブ移行が新規キャラにも走り、Lv50を超えているとレベルが水増しされる（Lv80なら101）。移行は v2 以前のセーブ専用の処理とする。
- セーブ読込は壊れた値で止まらないことを保証する。数値は有限値へ均して下限を掛け、配列であるべき項目は配列でなければ初期値に戻す。XPカーブ移行の探索ループは有限値で必ず打ち切る（旧Lv10万以上で累計XPが Infinity になり、起動時に固まって初期化ボタンにも辿り着けなかった）。管理者モードのレベル入力は任意の数を受けるため、この経路は常に開いている。
- 編成1番手は実際に潜るキャラクターで、装備とレベルはキャラクターごとに独立する。装備を持つキャラクターを編成から外すときは番手に関係なく、「全装備を外して倉庫へ戻す」か「装備したまま外す」かを確認する。入れ替え時は降ろす側と迎える側の装備数・レベルも示す。編成枠は深度11まで1枠しかなく、チュートリアル最終手順の入れ替えがそのまま「装備なしLv1で初回潜行」に直結していたため。
- 敵数は深度に比例して増えるが46体で頭打ち、速度も上限1.0の関数で決まる。
- 装備深度は生成深度の整数値、固定値の主能力・オプションは深度依存式で伸びる。割合オプションは100層で伸び切り、全7部位を最高値で厳選して指定上限付近へ届く。
- 装備オプション名は装備タブの全16ステータスと完全一致する。クリティカル率（初期1%）・クリティカル倍率（初期150%）・状態異常耐性・回避率は装備だけで増減し、能力ポイント・キャラ特性・潜行中強化・消耗品からは増えない。
- 100層最高厳選時の目安／上限は、ドロップ率25%、クリティカル率25%、状態異常耐性20%、回避率15%、攻撃速度250%、移動速度250%、ライフスティール10%、クリティカル倍率250%。
- 通常敵の装備ドロップ基礎率は4.8%、金42%、欠片13%、宝箱生成3.5%。装備の「ドロップ率」は装備・金貨・結晶・固有素材・回復物など確率抽選される戦利品へ共通倍率として乗る。レア度そのものは上げない。
- ボス/エリート/宝箱/壺は個別の確定または補正付き報酬処理を持つ。
- 効果ごとに時計を分ける。敵の減速弾は祭壇の残り時間を流用せず、専用の2秒タイマーで管理する。共有すると、祭壇の効果中に減速を受けたとき2秒のはずの減速が祭壇の残り時間（最大50秒）続き、疾風の祭壇は移動+28%が-35%に反転したまま張り付く。逆に祭壇の残りが2秒未満だと祭壇の方が延命される。
- 雑魚と樽は低確率で結晶、ボスは撃破ごとに核を1個落とし、いずれも現在深度の階梯になる。
- 帰還またはボス撃破で進行を保存する。死亡は同じフロア・同じ位置で再開し、敵、ボスHP、開封済み宝箱、危険床、未回収ドロップをリセットしない。通常プレイの開始深度は1・6・11…（1+5n）のみで、自由入力も直前の合法地点へ丸める。管理者・デバッグモードだけは任意の到達済み深度を指定できる。

## 経済（ゴールド、課金通貨、ガチャ）
- ゴールドは敵/宝箱/壺、装備売却で得て、合成、能力振り直し、商店購入に使う。
- 潜行中の取得ゴールドと装備は帰還時に確定し、全滅/断念では未帰還分を失う。
- 課金通貨は `premium`（◆）としてゴールドと別管理し、商店の購入操作で補充できる。
- キャラクターガチャは300◆、未解放キャラを優先して解放しプロフィール候補にも加える。
- 装備ガチャは200◆、最大到達深度相当の装備を生成し、最低でも上質を保証する。
- チュートリアルでは装備ガチャとキャラクターガチャを各1回無料で固定報酬にする。
- チュートリアルの進行は「詰まない」ことを最優先とする。誘導先が画面に無いときは入力制限を解除し、弾いた入力は黙って捨てずに案内を出し直す。練習部屋は保存されないため、練習中に再読込したら練習部屋の頭から再開する。潜行中の案内（練習部屋・ボス・帰還）は拠点では表示しない。
- 配置の検証は実ブラウザで行う（`npm run check:layout`）。ヘッドレスのDOMスタブには `querySelectorAll` も描画も無いため、ボタンの重なり・文字の切れ・画面外・スキップの到達可否はそこでしか捕まらない。数値が収まっていることだけを確認して通すと、丸い切り抜きで削れている状態を見逃す。
- スキップは案内バナーの中だけに置かない。バナーは「確認」で閉じるため、閉じた後はスキップ手段が消える（練習部屋で閉じると部屋に取り残される）。チュートリアルが終わるまで、案内の再表示とスキップをタブや画面に依存しない位置へ常駐させる。常駐バーを出す間は上部HUDと拠点ヘッダを下げ、HP/MPや所持金と重ねない。
- レア抽選、通常ドロップ率、ガチャ機能そのものは進行バランス変更の対象外とする。
- 倉庫の売却選択UIを分解にも流用し、装備中を除外した複数装備を確認後に結晶化する。
- 倉庫フィルタのレア度キーは `r0`〜`r4`、部位キーは部位名そのもの。判定は先に長さ2のレア度キーだけを拾う。頭文字だけで振り分けると `ring` がレア度側へ落ちて指輪フィルタが常に0件になる。

## 日替わり任務と日次ボーナス
- 端末ローカル時刻の4:00を日次更新とし、現在時刻から4時間引いたローカル日付を単一の日付判定関数から得る。
- 任務は「最大到達深度の半分以上（最低1）をクリア」「敵200体を撃破」「装備5個を分解」の3種固定で、進捗と受取状態を保存する。
- 深度任務の目標と任務報酬の結晶階梯は、受取時点の最大到達深度に追従する。3任務の達成後は全達成報酬として同階梯の核1個を受け取れる。
- 未受取報酬を含む任務状態は日次更新でリセットし、翌日へ持ち越さない。
- 日の最初の3潜行はその潜行中に拾う結晶と核を2倍にする。残り回数は既存の `S.stamina` に保存し、4潜行目以降は通常量に戻るだけで潜行自体を制限しない。

## 実装後の検証基準
- 検証上の1潜行は、深度1から目標深度までを順に降りきり、各フロアの実際の生成・撃破・ドロップ処理を通すものとする。素材経済と消耗品検査は同じ共有計測関数を使う。
- ヘッドレス戦闘botはゲーム本体のフロア生成、装備生成、戦闘 `update()` を実行し、各深度の複数試行から死亡率50%の境界を計測する。
- 到達時レベルは既存XP目安から、素手Lv10、標準Lv60、厳選Lv90とする（Lv100未満）。
## 難易度と、装備が意味を持つこと
- **その階層に見合った装備でなければ通らない。** 装備7部位の深度の平均を階層で割った比（`gearReach`）で、与ダメージが `GEAR_GAP_MIN`〜1.0 の間を動き、被ダメージはその逆数になる。空きスロットは深度0として数える。`GEAR_GAP_FREE`(8) 層までは見ない。
  - これが無かったころ、**Lv60・深度20の拾い物・3段目の道具で50階のボスに勝率92%** だった。実測すると、Lv60・深度20の装備は素手に対して攻撃+11%・HP+8%しかなく、力のほとんどをレベルが出していた。装備で潜るゲームになっていなかった。
  - 追いつき具合は隠さない。出撃バーと潜行前の確認、潜行中の深度表示に「装備 適正／不足／歯が立たない」と与被ダメージの倍率を出す。なぜ通らないのかが読めないと、装備を替えるという答えに辿り着けない。
- **ボスは長引くほど強くなる。** `BOSS_ENRAGE_AT`(45秒) を過ぎると与ダメージが毎秒 `BOSS_ENRAGE_RATE` ずつ上がり、同時に最大HPの `BOSS_ENRAGE_REGEN`×(倍率-1) を毎秒回復する。
  - 与ダメージを上げるだけでは足りない。被弾しない立ち回りができる人には何の歯止めにもならず、実測で**被弾を無視すれば深度20の装備でも50階ボスを87秒で倒せた**。回復が上回って初めて、火力が足りない装備では何時間かけても倒せなくなる。「時間をかけて慎重にやればどんな装備でも勝てる」を潰すのはこの一点。
  - 激昂は隠さない。ボスバーに倍率と「傷が塞がる」を出す。何が起きているか分からないまま殺されると、「長引かせない」という正しい答えに辿り着けない。
  - 実測（被弾を完全に無視して5分殴り続けた50階ボス）: 深度20→0/6・深度25→0/6・深度30→2/6・深度35以上→6/6。**関門は階層の6〜7割の深度**に立つ。
- **全体の手ごたえは敵の攻撃力だけで上げる**（`ENEMY_DMG_MUL`）。敵HPを上げると戦いが長引くだけで「時間をかければ勝てる」は変わらないうえ、**属性を合わせる価値が落ちる**。一撃で倒せていた相手が倒せなくなり、共鳴の4.5倍が「もう一振り」に吸われるため（実測: 敵HP1.15倍で 有利帯を合わせたビルドが片付ける速さが 無属性の1.50倍→1.25倍。攻撃力だけを1.8倍にしても1.50倍のまま動かない）。
- 死亡率50%の実測目標は、標準（希少7枠・品質1.00・半強化・Lv60）が38〜55、厳選（伝説7枠・品質1.30・最大強化・Lv90・0凸）が88〜108とする（旧: 55〜70 / 95〜115。難易度を上げる判断に伴って引き下げた）。存在可能なドロップ品質だけを使う。
- **50%死亡深度の二分探索はボス床を外して行う。** 5層ごとのボス床だけ死亡率が跳ね上がるため、探索結果は「たまたまボス床に当たったか」で決まり、階段状に飛んでいた（実測: 標準は 48層52% / 50層98% / 52層52%）。外すと素直に50%へ収束する（標準45層で46.3%、厳選97層で50.6%）。ボス床は別項目として、通常床より重いことを確かめる。
- **死亡率の差を判定に使うときは試行数を増やす。** 64回では死亡率1つの揺れが±6ptあり、その差はさらに大きく揺れる。判定の閾値と同じ大きさのノイズを乗せたまま合否を出してはいけない（実測で 7.8pt/8.0pt、18.8pt/15.0pt と閾値ぎりぎりの誤判定が出た）。192回まで増やす。
- 厳選プロファイルの攻撃力とHPをそれぞれ2倍（総合力2倍）にしたとき、50%死亡深度の増分を+10〜+20に収め、深度200以降は実質到達不能、深度1000でも全数値を有限に保つ。
- `npm run check` は構造回帰、上記botの目標範囲、強化経済の実測、深度1000への実際の潜行をまとめて検査する。
- 既存セーブは旧曲線の累積XPから新しいレベルと残XPを再計算し、旧上限後成長値を能力ポイントへ換算する。振り分け済みの6能力値は変更しない。
- 素材未保存の旧セーブは結晶/核とも0で開始し、深度3装備は何個分解しても階梯3以上を生まない。
- 階梯の旧定義で保存された結晶・核は、初回ロードで階梯キーを1つ下へ移す（階梯1は1に留めて合算）。
- 属性検査はゲーム本体の `enterFloor()` と `update()` を使う。火の5個共鳴・同一装備・同一レベル・同一乱数種で木優勢と水優勢の実フロアを全滅させ、不利帯の所要時間を有利帯の2.0倍以上とする。固定ダメージや合成した敵による倍率の再測定はクリア時間検査に使わない。さらに全属性で3/5/7個を実際に装備し、有利与ダメージ倍率が `3個 < 5個 < 7個` となることを検査する。
- 5属性の5個共鳴ビルドは `check-balance.mjs` と同じ48試行の二分探索と境界160試行で50%死亡深度を測り、属性間の差を±5以内、光・闇が火水木を3層以上上回らない範囲とする。無属性7個は5属性共鳴の平均より5〜15層低くする。普通・弱点の与ダメージは生成した実敵への実攻撃で測り、無属性の帯間時間比を1.2以下、深度150の不利帯でも進行可能に保つ。

## 調合・消耗品
- 消耗品は**系統×段階**で持つ。系統は癒血・闘気・鉄化・澄心・韋駄・震撼・緊縛・蝕み・篝・観・帰路の11。段階は最大3で、1段目は結晶だけで作れて効果が弱く短く、上の段ほど**固有素材**を要求して効果と持続が伸びる。
- 名前は既存作品と重ならないよう、この世界の言い回しで統一する（「◯◯の雫／霊薬／秘薬」など、系統名＋器の形）。素材名も同様に、一般名詞そのままを避ける。
- 固有素材（`PARTS`）は**決まった敵からしか落ちない**。結晶・核のような汎用材と違い、貯蓄では代替できない。これが調合の難易度そのものになる。汎用材だけで上位品が作れると、時間をかけるだけで最強の持ち込みがそろってしまう。
- 素材の等級は出どころの敵の解放深度に連動させる。浅い敵ほど低い等級、深い敵ほど高い等級を落とす。ドロップ率は等級で決め、7.5%／5.5%／3.5%／2.0%／1.0% とする。深度では変えない（深い敵は元々高い等級を落とすので、二重に効かせると深部で素材が過剰になる）。
- 固有素材は**売却できない**。金に換えられると、上位品の壁が金策で崩れる。
- 効果が強い系統ほど上位段の素材を稀にする。回復・攻撃・防御の3段目は `riftcore`（分裂体とボスからのみ）を要求する。
- 倉庫の「素材」タブは所持数一覧を先頭へ置き、結晶・核の全段階と全固有素材を一画面の高密度グリッドで見渡せるようにする。各素材の**出どころの敵名とドロップ率**は折り畳み内に併記し、必要なときだけ開く。作れないときに「では何を狩ればいいのか」がその場で分かる必要がある。
- 等級の色分けは装備と同じ表（並/上質/希少/秀逸/伝説）を消耗品・素材にも使う。等級体系を別に作ると「この色は強いのか」を二度覚えることになる。
- **枠の色＝等級、絵の色＝系統**と役割を分ける。枠を系統色にすると、同じ系統の1段目と3段目が同じ見た目になり、強い品と弱い品が並んで見分けられない。
- 消耗品の絵は系統ごと、素材の絵は素材ごとに別の輪郭を持たせる。同じ形を色違いで使うと、小さいアイコンでは判別できない。
- 持ち込みは拠点の編成・開始階層と同じ画面に4枠を置く。持ち込み上限は品ごとに1〜5個で、上位段ほど少ない。同一品を複数枠に設定しても在庫総数を超えて複製しない。
- 道中で拾える回復薬の上限（`runMax`）は段ごとに変える。1段目は6個、2段目5個、3段目3個。一律6個にすると、苦労して作る上位の回復薬が道中で拾い放題になり、調合の難しさが意味を失う。
- HUDの旧ポーション位置を単一のアイテムボタンとして使う。タップは選択枠、360ms長押しは4枠を扇状表示し、スライドして離した枠を使う。扇表示は `S.paused` を変更せずゲーム更新を継続する。
- 使用にはキャンセル不能の0.5秒行動硬直と、全品共通8秒クールダウンがある。最弱の回復薬 `mend1` だけは、それ自体を持ち込み枠へ設定している場合に限り樽から出現し、その枠に空きがある場合だけ拾える。上位回復薬を持ち込んでも `mend1` は出ず、別の回復薬枠へ変換して補充もしない。
- 使用時に倉庫在庫を減らすため、死亡・断念時にも未使用数は失われない。旧 `pots` セーブは初回だけ回復薬3個へ移行する。

## Bundle B: 戦術アイテム・操作モード・課金導線
- 既存の調合、4〜6枠の持ち込み、0.5秒硬直、全品共通8秒クールダウンに、音爆弾（周囲3秒スタン）、しびれ罠（同時1個、4秒麻痺）、弱体の霧（15秒、防御25%低下）、松明（視界1.6倍、90秒）、探知の香（当該フロアの宝箱・祭壇・階段をミニマップ表示）、帰還の巻物を追加する。いずれも直接ダメージを与えない。
- 帰還の巻物は直近の被弾から5秒間使用不可。安全時に3秒詠唱し、完了時だけ消費して戦利品を保持したまま帰還する。詠唱中の被弾では中断し、消費しない。
- 操作モードはフル手動、片手、完全オート。片手は全面ドラッグ移動と非ドラッグの通常攻撃で、スキル・アイテムを自動化する。完全オートは最大到達深度より浅い開始深度でのみ選択可能。自動行動は条件成立から0.35秒後で、自動スキルだけ62%威力、アイテムは補正なしとする。
- 片手操作は移動をドラッグ入力に残し、射程内の通常攻撃を継続する。完全オートは最寄りの敵が通常攻撃の射程に入ると移動を止めて敵へ向き直り、射程外ではマップの歩行可能セルを経由する。移動停滞を検出した場合は経路を更新して壁を迂回する。
- 自動条件は指定された8語彙、行動はスキル3種・アイテム枠4種・何もしないに限定し、最大6スロットを上から評価する。実行不能な行動は飛ばす。積極・温存・生存優先の3プリセットを標準提供し、編集表示は任意で開く。
- ジェム商店は純化触媒、復活の羽、恒久持ち込み枠を販売する。決済はダミーであり、購入品は `paidInventory` に個体ID、生成元、生成時刻を持つレコードとして保存する。通常経路は購入関数だけが生成し、管理者付与は `admin: true` と `source: admin` を記録する。
- 復活の羽は潜行ごとに1個まで消費してHP50%・2秒無敵でその場復活する。持ち込み枠は2回まで購入でき、上限6枠。純化触媒は下位結晶4個を上位結晶1個へ即時変換する。

## Bundle B 実測基準
- ヘッドレスブラウザでゲーム本体の `update()` とアイテム関数を実行し、帰還の使用禁止・詠唱・被弾中断・結果画面表示を伴う完了時消費、および購入個体IDを検査する。被弾中断は回避不能かつ被弾可能な状態を先に確定して検査する。自動化の反応遅延は条件成立から行動まで `update()` を60分の1秒刻みで計時し、設計値0.35秒以上かつ0.40秒未満であることを検査する。自動スキル倍率は同一乱数・同一対象への実ダメージ比から求める。
- 同一Lv60・同一希少装備プロファイルの50%死亡深度は、戦術品なしを基準として戦術品を含むフル持ち込みとの差を+1〜+3に収める。操作別は3モードとも同じ接敵の与え方で測り、フル手動が最も深いことを条件とする（片手と完全オートは戦闘部分が同じ自動化なので両者の大小は問わない）。
- 消耗品検査は**1段目だけの持ち込み**と**3段目までそろえた持ち込み**を別々に測る。ただし到達深度そのものでは判定しない。50%死亡深度は段差の粗い階段関数で、死亡率が10ポイント以上動いても境界が1深度も動かないことがある（実測: 深度57で死亡率 50%→42%→25% と差が出ているのに境界は 57/55/62 とほぼ動かなかった）。属性検査と同じ理由で、**同一深度での死亡率の差**を基準にする。
- 基準深度は「持ち込みなしの50%死亡深度」とその±5の3点。1段目の改善は3ポイント以上（無いよりまし）、3段目の改善は15〜40ポイント（装備より持ち込みが効いてしまわない範囲）、両者の差は8ポイント以上とする。
- **1段目の上限は絶対値ではなく上位段との比で見る**（上位段の70%以下）。守りたいのは「上位品を作る動機が残ること」であって、ポイントの絶対値ではない。敵の攻撃力を上げると、同じ軽減率でも防げる量が増えて絶対値は自然に大きくなるので、絶対値の上限は難易度を動かすたびに意味を失う（実測: 攻撃力1.8倍で1段目の改善が 15.6pt まで上がったが、上位段も 26.0pt へ上がっており、比は60%で健全だった）。
- **消耗品を使う模擬は、品目のIDではなく効果で判断する。** `key==='mend1'` と書いていたため、上位段に `mend3` を持たせても一度も飲まず、上位段を不当に低く測っていた（上位段の改善 20.3pt → 修正後 26.0pt、段階差 4.6pt → 10.4pt）。段階差が小さく見えたのは仕様ではなく検査の誤りだった。
- 実測基準の到達点（2026-08-15）: 1段目 −10.4pt、3段目 −22.9pt、段階差 +12.5pt。
- 深度12を60秒更新し、完全オートと片手操作は開始敵数の20%以上を討伐し、通常攻撃の射程に入ったtickが0でないこと。敵がフロア全体に散るため移動時間が支配的で、正常動作でも討伐率は2〜4割になる。完全オートでは1秒の移動量が0.25未満となる秒数を20秒以下とし、壁への停滞も検査する。片手の移動入力は経路探索に追従させる（直線入力では壁に張り付いて射程に入れない）。
- 戦術品の寄与も1段目と上位段を分けて測り、到達深度ではなく同一深度の死亡率差で判定する。1段目（結晶だけで作れる）は1〜15ポイント、上位段（固有素材が要る）は6〜40ポイント、両者の差は3ポイント以上とする。ここが逆転していると、深く潜って素材を集める理由が無くなる。実測（2026-08-15）: 深度55で なし53.1% / 1段目51.6%(-1.6pt) / 上位段39.1%(-14.1pt)。
- 属性の価値は**死亡率では判定しない**。この検査の勝敗は「90秒で敵を掃除しきれたか」で決まるため、深度に対してほぼ二値で切り替わる（実測: 深度40で死亡率2.5%、深度45で92%）。その外側ではどのビルドも0%か100%に張り付く。実際、同じ検査が深度57〜67では +18.8pt、深度50〜60では -1.6pt を返したが、両者のゲーム本体の難度は同一だった（同一条件の実測で 92.2% と 90.6%）。符号すら標本位置で変わる指標は判定に使えない。飽和しないクリア時間で測る。
- 判定は「同じ有利帯を、帯に合わせたビルドと無属性で走らせたときのクリア時間比」で、1.25倍以上を要求する。
- **クリア時間の測定は装備深度を戦うフロアに合わせる**。以前は深度50固定の装備で深度29〜32を殴っており、敵HP250〜530に対して通常攻撃が505〜666と、どのビルドも全敵を一撃で倒していた。属性倍率は過剰火力に吸われ、有利でも不利でも同じ秒数になる（この状態での実測差は1.10倍しかなく、属性が効いていないように見えていた）。装備とフロアを揃えると本来の差が出る。
- 測定フロアは有効な帯を選ぶ。51〜55は木優勢（火が有利）、46〜50は水優勢（火が不利）。これより深いと不利帯で火ビルドが倒れて秒数が取れず、浅いと一撃圏に戻って差が消える。
- 実測（2026-08-15、装備＝フロア深度）: 有利19.03秒／不利36.55秒（帯間比1.92）、無属性の有利帯25.20秒（合わせた速さ1.32倍）、無属性の帯間比0.89（帯に依存しない）。深いほど属性は強く効く（深度71で1.57倍、深度91では無属性が150秒でも討伐しきれない）。設計意図「帯に合わせるのが一番深くまで行ける」は成立している。
- 死亡境界は単一深度ではなく、開始深度から8深度分の死亡率を均等な試行数で平均して判定する。戦術品の切り分けでは音爆弾、しびれ罠、弱体の霧、松明、探知の香、帰還の巻物を単品でも測り、松明・探知の香・帰還の巻物は探索品3種としてもまとめて測る。
- 2026-08-10 の8深度周期化後の調査値は、戦術品なし55、各戦術品単品55、探索品3種55、消耗品込み戦術フル63だった。一方、同じ周期化を消耗品検査へ適用すると、持ち込みなし55、消耗品フル63（差+8）となった。したがって単一深度で見えていた戦術差+10を音爆弾だけの過剰効果とは判定できず、禁止対象である消耗品の差が先に目標を外れるため、戦術品の実装値は変更しない。


## アカウントランクと希少敵
- 最上部はキャラクター別レベルではなく、全キャラクター共通のプレイヤーランクを示す。帰還成功時だけ到達深度の1.4乗に比例する経験値を確定し、浅層往復より深く潜る判断と、失う前に帰る判断の両方を作る。キャラクターLvは仲間・装備画面に残す。日次ボーナス回数は任務欄に残し、最上部の通貨説明には表示される通貨だけを書く。
- 燦めく軟泥は通常の敵構成比を崩さない別枠0.5%で出現する。全補正と状態異常処理の後で1回1ダメージへ制限し、HPは深度平方根で10から増えて30で止める。深部で撃破時間が際限なく延びないための上限である。経験値はその深度の通常敵平均（深度加算込み）の50体分とし、キャラクター経験値だけに入れる。管理者の `forceMetal` は確率を写さず実体を確定生成して検査する入口である。

## 攻撃の予兆と表示
- 突進斬りと同じ挙動を使う疾駆は、発動から0.30秒の移動終了まで全ダメージに無敵とし、終了後0.18秒の既存猶予も残す。同じ操作に技名だけで異なる防御挙動を持たせないためである。
- 毒沼は最初の1枚を足元へ置き、残りだけ周囲へ散らす。棒立ちを安全解にせず、即死ではなく0.4秒周期の既存判定で移動を促す。影の背後攻撃は出現した敵を中心に0.45秒の見える予兆を出してから爆発させ、動かなければ当たり、離れれば避けられる攻撃にする。
- 技一覧は用途タグではなく通常攻撃比を表示し、説明は押した結果だけを一行で書く。装備マスは空きを含めて部位名を省き、部位ごとに描き分けたアイコンで判別する。

## 固有技の等級差と装備画面の統合
- 攻撃技の表示倍率は通常攻撃比で最大2.00倍とし、共通技も固有技も例外を作らない。固有攻撃は技ごとの1発倍率へ `N=1.00 / R=1.06 / SR=1.12 / SSR=1.20` を一度だけ掛け、`uniqueDamage()` で2.00へ上限処理する。大技や広範囲技の個性は9倍・20倍の瞬間火力ではなく、範囲・貫通数・移動・状態異常・消費MP・再使用時間で作る。
- 自己強化も同じ等級表を軽減率と回復率へ掛ける。キャラクター固有の基礎能力補正とは別系統なので、合算後の実戦差は検査で明示し、等級倍率を固有技へ二度掛けない。
- 拠点の折りたたみは日替わり任務だけにし、限界突破は装備画面の第4区画へ移す。重複獲得が突破条件なので、次段階は「同じ仲間 0/1」と表示する。
- 装備画面上部は、押せるキャラクターアイコン、4区画ボタン、名前・等級・Lv・職業・戦闘力の1行を高さ74〜78pxの一ブロックへ統合する。4区画のタップ領域は44pxを維持する。キャラクターを替えても開いていた区画を維持し、保存値が無い場合は装備を開く。
- 技候補は全件を縦カードで積まず、先に3つの装備枠を選び、候補を3列のボタン格子で選ぶ。説明は現在変更中の技だけ一行表示し、各候補の全文は `title` に保持する。390×844で最も長かった技区画のスクロールを優先して無くすためである。

### 自己点検での補正
- 希少敵の継続ダメージは、通常敵と同じフレーム連続減算を通さない。最終的な1ダメージ制限をフレームごとに掛けると、制限したつもりが毎秒60ダメージになるため、経過時間を蓄積し、1秒ごとの1回として通常の被ダメージ関数へ通す。
- 希少敵の別枠率は `METAL_CHANCE` に集約する。1000フロアの固定乱数列でも要求範囲を確認でき、検査側へ確率を書き写さずに済むためである。
- 装備マスの部位名は空き枠を含めて表示しない。今回の受け入れ条件が全 `.slot` からの削除を明示したため、以前の「空きだけ部位名を残す」判断を取り下げ、空きも部位アイコンで判別する。
- 技説明は一行固定とし、幅を超える場合は省略表示にして全文を title に残す。カードの高さを説明文の長さで変えず、390px幅の一覧で折り返しを起こさないためである。
- 通常攻撃の基準化後も既存の到達深度目標を緩めないため、敵HP曲線は深度35/60/80を18/38/65から24/52/72へ上げ、深度100の148へ合流させる。初回実測では標準の50%死亡深度が目標38〜55に対して65、通常床死亡率が目標42〜70%に対して20.8%となり、通常攻撃強化で中盤だけが明確に軽くなっていた一方、厳選は102で目標内だった。そのため全域ではなく中盤を中心に補正し、深部の到達感を保つ。
- 1回目の中盤HP補正後も標準50%死亡深度62・通常床死亡率32.5%で目標外だったため、深度35/60/80/100を36/85/100/170へ再調整した。単にHPを上げるのではなく、通常攻撃2倍によって短縮された交戦時間を戻し、同深度装備でも通常床に死亡リスクが残る既存目標へ合わせるためである。
- 2回目は標準到達42で範囲内になった一方、通常床死亡率72.1%が上限70%を2.1ポイント超えたため、深度35/60だけを34/80へ小幅に戻す。深度80以降は厳選の通常床25.5%が下限付近で成立しているため動かさない。
- 攻撃技を通常攻撃比2倍以下へ揃えた後の再計測では、厳選の到達102は維持したが通常床死亡率だけ24.0%となった。敵攻撃力を1.80→1.82へ上げても値が変わらず、原因は被ダメージではなく45秒内の掃討不足と確認できたため、その変更は撤回した。標準帯へ触れない深度80/100の通常敵HPだけを100/170から102/174へ約2%補正する。
- 補正後の総合実測は、50%死亡深度が素手9 / 標準44 / 厳選102、通常床死亡率が標準64.6% / 厳選25.0%、総合力2倍の伸びが+12層となり、既存目標をすべて維持した。属性検査も有利帯が不利帯の1.93倍速、帯合わせが無属性の1.33倍速で成立した。
- 中深度HP曲線を既存難度へ戻した後、固定共鳴の到達深度が水35〜光49（全幅14）となった。光闇は不利帯が少なく固定運用でも過剰に残るため、中/強共鳴の与ダメージを5.0/6.5から4.2/5.7へ下げる。帯に合わせる価値はクリア時間で別途維持しつつ、光闇を固定するだけで有利になる状態を避けるためである。
- 与ダメージ倍率の小幅変更では固定光共鳴の到達49が動かなかったため、その変更は撤回する。原因は火水木には不利帯が2つずつある一方、光闇は対属性の1帯しか被ダメージ上の弱点がないことだった。光闇共鳴中は火水木からの被害を1.15倍とし、対属性は従来どおり共鳴段階の `danger` を使う。希少属性の火力個性を残しながら、固定運用の安全性だけを補正するためである。
- 状態異常表の燃焼・毒も別の継続減算経路を持つため、希少敵では状態ごとに1秒を蓄積し `hurtE` へ通す。自己点検で1.02秒後の燃焼1.23・毒0.49となり、直接dotだけの修正では「すべて1ダメージ」を満たしていないと判明したためである。
- 希少敵の最終減衰は「上限1」ではなく、全補正後に正のダメージなら固定1とする。装備深度差で状態異常が0.18/0.07まで下がった実測を受け、「1しか減らない」の表示と挙動を一致させるためである。
# 装備画面の部位別操作

- 最上部プロフィールは名前と戦闘力を同じ行に置き、ランクを次の行に置く。戦闘力を常に確認できるため、装備本文には重複する戦闘力帯を置かない。
- 7部位の枠を押すと、プロフィールと最下部タブを残したまま部位専用画面へ切り替える。これは、現在品・操作・候補を一画面で確認し、ポップアップを往復する手数を減らすためである。
- 候補は選択部位と現在の職業に装備できる品だけを表示する。候補を押した比較では変更前後の能力、オプション、`combatPower` の増減を表示してから装備を確定する。
- 一括おすすめは独立した帯を作らず、部位専用画面の操作群に置く。操作領域は44px以上を維持する。

## 装備の選択処分・引き上げ・比較

- 倉庫の売却・分解は、開始ボタンを押してから複数の装備を選ぶ方式とする。選択はレア度枠と混同しない水色（`#6ad8ff`）の内側アウトラインと文字印で示し、固定下部バーに合計報酬、実行、キャンセルを横並びで置く。処分前に対象数と報酬総量を確認するのは、意図しない一括処分を防ぐためである。
- 装備中の品は一括処分では選べない。候補から外すことで、多数選択中に重要品を見落として外してしまう事故を防ぐためである。装備中の品を処分するときは、従来どおり部位画面で個別確認を通す。
- 装備詳細から保護をON/OFFできる。保護中は錠前印を表示し、一括・個別を問わず売却、分解、強化素材、継承素材に選べない。保護状態は装備UIDとともに保存し、帰還・再起動・キャラクター間移管で失わない。
- 帰還成功時の未鑑定装備は7部位すべてを共通の抽出処理で倉庫へ移す。既存UIDとの重複だけを除外し、手袋など特定部位を分岐で落とさない。保存と再読込後も同じUID・保護状態で存在することを回帰検査する。
- 階層引き上げは伝説装備だけを対象とする。伝説以外でもボタンへの操作は受け付け、その場で「引き上げは伝説の装備にだけ使えます」と理由を表示する。無反応や無効色だけでは条件を理解できないためである。
- 装備比較の変更前・変更後には各装備自身の素の性能を表示し、その下に独立した「増減」を置く。増減は `derive()` と `deriveWith(slot, item)` の結果が変わる項目だけを緑／赤で示し、`combatPower` の変更前後と差も同じ枠に含める。行が多い場合は増減枠だけを最大150pxでスクロールさせ、操作ボタンと画面全体を押し下げない。

## 道中回復の出どころと戦士の密着攻撃

- 回復薬は敵から落とさず、最弱の回復薬 `mend1` を持ち込んだ潜行だけ、樽から12%で落とす。持ち込んでいない潜行ではドロップ自体を生成しない。樽を探して壊す行動に使用した分の補充という意味を持たせるためである。回復薬の抽選後も `return` せず、ゴールド・破片・装備の抽選を続ける。回復薬を出やすくしたことが既存報酬を押しのけないためである。
- 通常敵は別枠5%でハートを落とす。ハートは持ち込み枠へ入らず、その場で最大HPの4%を回復する。満タンでは拾わず薄く表示して残し、負傷したときに利用できる回復を無駄にしない。負傷時は通常の吸着対象とするが、満タン時は吸着させない。
- 戦士の通常攻撃は既存の扇判定を全威力で優先し、扇から外れても剣線が始まる射程55%以内なら全周の内側補完判定を半分の威力で当てる。分岐は排他的にし、密着座標で角度が不安定でも外れず、同じ敵へ二重に当たらないようにする。
