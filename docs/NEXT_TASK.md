対象リポジトリ: `ITK03/Hack_and_Slash`
作業ブランチ: `claude/diablo-style-hackslash-game-khlbrr`

## 守ること（このリポジトリの決まり）

- **外部ライブラリを足さない。** ビルド工程も増やさない。`public/index.html` 単体で動くこと。
- **検査スクリプトにゲーム本体の式・定数・確率を書き写さない。** 必ず `public/index.html` を
  読み込んで、その中の関数と状態を呼んで計測する（`scripts/game-env.mjs` の `loadGame()`）。
- **`npm run check` が通らない状態で完了報告しない。** 併せて `npm run check:layout` /
  `check:playable` / `check:ui` も通すこと（この3つは Playwright を使うので `npm run check`
  には含まれていない。ブラウザが無い環境では自動でスキップされる）。
- **目標値・探索範囲・チェック内容を緩めて通すことは禁止。** 目標を満たせないなら、
  満たせなかった事実と実測値をそのまま報告する。
  ただし *設計そのものを変える指示* を受けた項目については、目標を動かしてよい。
  そのときは「緩めたのではなく狙いを変えた」と分かるように、旧値・新値・理由を併記する。
- **計測が目標を外れたら、まず「ゲームが壊れている」のか「計測方法が実態と合っていない」のかを
  切り分ける。** 基準を動かしてよいのは後者と確認できた場合だけで、何をどう確かめたかを併記する。
- `docs/SPEC.md` を、変更した内容とその理由で更新する。「何をしたか」ではなく
  **「なぜそうしたか」** を書く。
- コミットメッセージは日本語で、理由を書く。モデル名は書かない。

## 依頼1: 通常攻撃を2倍にし、戦士3技を通常攻撃の倍率で定義し直す

**通常攻撃の威力を2倍にする。** `CFG.ATK_MUL` を `.34` → `.68`。

そのうえで、戦士の3技を**通常攻撃に対する倍率**で定義し直す。

| 技 | 要求倍率（2倍にした通常攻撃に対して） |
|---|---|
| 薙ぎ払い (`cleave`) | 通常攻撃の **1.3倍** |
| 突進斬り (`dash`) | 通常攻撃の **1.5倍** |
| 大地砕き (`slam`) | 通常攻撃の **1.7倍** |

### 実装上の注意（重要）

現在の式は `public/index.html` の `pDmg(base,mul)`:

```js
function pDmg(base,mul){ ... return (rr(base[0],base[1])+p.d.atkFlat)*m; }
```

- 通常攻撃: `pDmg(C.atk, CFG.ATK_MUL)` … `ATK_MUL = .34`
- 技: `pDmg(sk.dmg)` … 倍率なし、技ごとの独自レンジ `dmg:[69,99]` 等

**`atkFlat`（装備由来の攻撃力）が掛け算の前に足される**ため、技に独自レンジを持たせたままでは
装備が育つほど倍率が変わってしまう。「常に通常攻撃の1.3倍」を成立させるには、
技のダメージを**通常攻撃と同じ式から導く**必要がある:

```js
pDmg(C.atk, CFG.ATK_MUL * sk.mul)   // sk.mul = 1.3 / 1.5 / 1.7
```

### 事前に測った現状と、変更後の見込み

現在の技は**通常攻撃の3.2〜7.2倍**で、しかも装備が育つほど比率が下がっている
（`atkFlat` が掛け算の前に足されるため）。

通常攻撃2倍と技の倍率化を**両方入れた場合**の見込み:

| 条件 | 通常攻撃 | 薙ぎ払い | 突進斬り | 大地砕き |
|---|---|---|---|---|
| 序盤 Lv5 素手 | 19 → **38** | 123 → 50（**0.40倍**） | 137 → 57（**0.42倍**） | 131 → 65（**0.50倍**） |
| 中盤 Lv40 深度40 | 128 → **255** | 442 → 332（**0.75倍**） | 456 → 383（**0.84倍**） | 450 → 434（**0.96倍**） |
| 深部 Lv80 深度100 | 194 → **388** | 638 → 504（**0.79倍**） | 652 → 582（**0.89倍**） | 645 → 660（**1.02倍**） |

読み方:
- **通常攻撃はどこでも2倍。**
- **中盤以降の技はほぼ据え置き**（0.75〜1.02倍）。
- **序盤の技だけが半分以下になる**（0.40〜0.50倍）。いま序盤の技が通常攻撃の6〜7倍と
  突出しているのが均される。狙いどおりだが、**練習部屋と序盤の手ごたえは確実に変わる**。
  チュートリアルの文言（「薙ぎ払い：強めの攻撃をしたい時に使います」等）が
  実態と合っているか確認すること。

バランス検査（`check-balance` の到達深度、`check-playable` のボス火力関門と
装備の深度差、`check-bundle-b` の操作モード別、`check-consumables`）は確実に動く。
**全部を測り直し、変わった値を前後で並べて報告すること。**

特に **`check-playable` のボス火力関門**（「被弾を無視して5分殴っても、階層の6割未満の
深度の装備では50階ボスを倒せない」）は、通常攻撃2倍で関門の位置が変わる。
関門が消えていないか（深度20の装備で倒せるようになっていないか）を必ず確認する。

### 併せて判断が要る点（実装したうえで報告する）

1. **他の技との整合。** `SKILL_POOL.warrior` には `whirl` `charge` 等、魔術師側にも別の技がある。
   3技だけ倍率制にすると同じプール内で定義が2種類混在する。
   → **全技を `mul` 方式へ揃えることを推奨**（既存の `dmg` レンジから現状比を割り出して
   近い `mul` を割り当てる）。採用可否は実装後に報告して指示を仰ぐ。
2. **再使用時間との釣り合い。** 倍率だけ見ると持続火力は
   薙ぎ払い 1.3/0.55秒 = 2.36倍/秒、突進斬り 1.5/2.2秒 = 0.68倍/秒、
   大地砕き 1.7/5.0秒 = **0.34倍/秒** となり、**大地砕きが薙ぎ払いの1/7**になる。
   このままだと大地砕きを選ぶ理由が範囲攻撃と気絶だけになる。
   → まず指示どおりに実装し、そのうえで「再使用時間かMP消費の見直しが要るか」を
   実測（持続火力の比）とともに報告する。**勝手に倍率を変えない。**
3. **通常攻撃と技の関係。** 通常攻撃が2倍・技が1.3倍だと、
   薙ぎ払い（MP12・再使用0.55秒）は通常攻撃の1.3倍でしかない。
   MPを払って撃つ意味が残っているかを、持続火力とMP回復速度から確かめて報告する。

## 依頼2: 突進斬りに無敵時間

**スキル発動の瞬間から移動が終わるまで無敵。**

該当箇所は `useSkill` の `case "dash"`（`p.dashT=.30` を設定している行）。

- 現状: 突進中は**接触ダメージだけ**が無効（`update` 内の `if(p.dashT<=0)` 判定）。
  弾・爆発・ボスの攻撃は通る。突進終了時に `p.invulT=.18` が付くだけ。
- 対応: 発動時に `p.invulT = Math.max(p.invulT, p.dashT)` を設定する。
  終了時の `.18` の猶予はそのまま残す（着地際の被弾を防ぐ既存の意図）。
- `hurtP` は冒頭で `p.invulT>0` を見て弾いているので、これで全ダメージ源に効く。

**注意:** 疾駆（`charge`）も同じ `k:"dash"` を使う。同じ無敵を与えるかは設計判断。
→ **与える前提で実装し、報告すること**（同じ挙動の技で無敵の有無が分かれると読めないため）。
併せて、無敵が強すぎないか（突進の連打で無敵を繋げられないか）を
再使用時間と突進時間から確認して報告する。

## 依頼3: 毒沼が自分に当たらない不具合

**症状:** 毒を撒く敵の攻撃が自分に向かって来ないので、棒立ちしているとダメージを受けない。

**原因は特定済み。** `bossRelease` の `telK==="pools"`（毒棘の女王 / `zoner`）:

```js
for(let i=0;i<(e.phase===2?5:3);i++){
  const a=rnd()*TAU, r=rr(1.5,4.5);
  S.fx.push({t:"pool", x:p.x+Math.cos(a)*r, y:p.y+Math.sin(a)*r, ...});}
```

沼を**プレイヤーから半径1.5〜4.5のリング上**に置いている。中心（プレイヤーの足元）には
**構造上絶対に落ちない**。だから動かなければ当たらない。

**対応方針:**
- 少なくとも1つは**足元（半径0付近）**に落とす。残りは周囲に散らす。
- 「立っている場所が危険になり、動かされる」形にする。沼で足止めして距離を取るという
  この敵の役割（`d:"毒の沼を撒いて距離を取る。沼を踏まずに追い詰める必要がある"`）を壊さないこと。
- 沼は `pool` fx で `f.tick` ごとに判定するため、置いた瞬間に即死させる作りにはしない。

**確認:** 同じ「リング状に置く」書き方が他の攻撃にも無いか探し、あれば同様に直す。
`check-playable` に「棒立ちしていると毒沼のダメージを受けるか」を追加すること。

## 依頼4: 闇の敵の背後突進が回避不可能

**症状:** 闇の敵が背後に回って突進してくるが、絶対に回避できなくて強い。

**原因は特定済み。** `bossRelease` の `telK==="ambush"`（影の簒奪者 / `vanisher`）:

```js
const a=Math.atan2(p.y-e.y,p.x-e.x)+Math.PI;
const tx=p.x+Math.cos(a)*1.1, ty=p.y+Math.sin(a)*1.1;
if(walk(tx,ty,e.r)){e.x=tx;e.y=ty;}
S.fx.push({t:"boom", x:p.x, y:p.y, tm:0, R:2.2, col:e.col, dmg:e.dmg*1.5, en:1, ...});
```

回避不能な理由は3つ重なっている:
1. 爆発が**プレイヤーの現在地そのもの**（`x:p.x, y:p.y`）を中心に置かれる。
   自分を中心にした円からは、原理的に外へ出られない。
2. `boom` は **最初のフレームで即座に判定する**（fx 処理の `if(first)` 内で `hurtP`）。
   猶予が1フレームも無い。
3. 予備動作 `e.tel=.35*tm` の間、敵は `vanish` 中で**姿が見えない**。
   どこから来るかの手掛かりが無い。

**対応方針（避けられる攻撃にする。弱くするのではない）:**
- 爆発の中心を**プレイヤーの現在地ではなく、出現した敵の位置**にする。
  背後に出るという挙動は残しつつ、離れれば当たるようにする。
- 出現から爆発までに**目に見える予兆と猶予**を作る（着弾点を先に描く、
  もしくは通常の予備動作と同じ見せ方にする）。避ける操作が間に合う長さにすること。
- 消えている間も**行き先の手掛かり**を出す（例: 出現予定地に印）。
  「消えている間に位置を変えるのが正解」という設計意図（コード内コメント）を
  プレイヤーが読み取れるようにする。

**確認:** 修正後、「動かなければ必ず当たる／動けば避けられる」ことを実測で示す。
`check-playable` に「その場から動けば避けられること」を追加する。
`ambush` 以外にも `x:p.x, y:p.y` を中心に即時判定している攻撃が無いか探し、あれば同様に扱う。

## 依頼6: プレイヤーランク

**要件:**
- ランク機能を追加し、**最上部バーに表示**する。
  いまキャラクターのレベルを出している場所（`<div class="hdrLv"><b id="hdrLv">Lv1</b>` と
  経験値バー `#hdrXp`）を**プレイヤーランクに置き換える**。
- ランク経験値は**遊ぶほど貯まる**。**深い層ほど多くもらえる。**
- **帰還しないと手に入らない**（死んだら入らない）。

**実装の要所:**
- キャラクターのレベル (`S.base.lv`) は**キャラクターごとに別**で持っている
  （`characterStates[key].base`）。ランクは**アカウント全体で1つ**の値にすること。
  `S` の直下に持ち、セーブ（`save()` / `load()` の両方）に必ず含める。
- 付与地点は `endRun(alive, cause)` の中の `if(alive)` の枝。
  死亡時（`else`）には**一切入れない**。
- 深度に対してどう増やすかの式は判断してよいが、次を満たすこと:
  - 浅い層を往復するより、深く潜って帰るほうが必ず得になる。
  - 途中で死ぬと丸ごと失うので、「引き際」の判断が意味を持つ。
- ランクが何に効くのか（見た目だけか、何かが解放されるのか）は**今回は決めない**。
  まず「貯まる・見える・帰還しないと入らない」だけを作り、
  **効果の案を実装後に提示すること。**

**注意:** キャラクターのレベルは今も育成の中心なので、
**最上部から消えても他の場所（仲間タブ等）では読めるようにしておく**こと。
経験値バーを置き換える以上、「レベルアップが近い」ことが分からなくなる箇所が無いか確認する。

## 依頼7: 経験値を大量に落とす希少な敵（メタルスライム枠）

**要件:**
- **経験値は通常敵50体分。**
- **防御力が異常に高く、基本1ダメージしか通らない。**
- **HPは1層で10。深く行くほど高くなる。**
- **出現率0.5%程度**の、めったに出ない敵。
- **目立つエフェクトが欲しい。**

**実装の要所:**
- 敵の定義は `ET`（`caster:{n:"呪術師",hp:32,sp:1.7,dmg:24,r:.32,aR:7,cd:3.0,xp:24,col:...,ai:"kite",...}`
  のような表）。生成は `spawnE(k,x,y,fl,elite)`、フロアの抽選は `enterFloor` 内の
  `avail` / `bag` / `pick(bag)`。0.5%は `bag` の抽選とは**別枠**で扱ったほうが確実
  （`bag` に混ぜると他の敵の比率まで動く）。
- **1ダメージ固定は現状の仕組みに無い。** `hurtE` に、この敵だけダメージを
  一定値まで切り詰める処理を足すことになる。**次の点に必ず注意する:**
  - `hurtE` には既に 操作モード減衰 (`ONEHAND_DMG`/`AUTO_DMG`)、装備の深度差
    (`gearOutMul()`)、属性倍率、正面防御などが乗っている。切り詰めは**それら全部の後**に置く。
  - **状態異常の継続ダメージ（燃焼・毒）**も同じ扱いにするか決めること。
    素通りすると「1ダメージしか通らない」が嘘になる。
  - ダメージ表示（`dnum`）に 1 が出ること。
- **HPの伸び方に上限の考えが要る。** 1発1ダメージ固定でHPだけ深度に比例させると、
  ある深度から**撃破が事実上不可能**になる。攻撃速度と技の手数から
  「深度Nで倒し切るのに何秒かかるか」を**実測**し、
  逃げられる前・囲まれる前に倒し切れる範囲に収めること。
  上限を置くか、伸び方を緩やかにするかは判断してよいが、**実測値を根拠に決めて報告する。**
- **経験値50体分**は「その深度の通常敵1体あたりの経験値 × 50」で計算する。
  現在の付与は `gainXP(e.xp + S.floor*2)` なので、深度込みで数えること。
- エフェクトは既存の `S.parts` / `S.fx` / `burst()` / `SFX` の仕組みで作る。
  **ミニマップにも出す**こと（`drawMM` の印は `known()`（踏み込んだ場所）で
  絞られているので、その規則には従う）。

**併せて確認・報告すること:**
- ランク経験値（依頼6）も50体分入るのか、**キャラクター経験値だけ**なのか。
  → **キャラクター経験値だけを想定**しているが、実装して報告すること。
- 出現が0.5%だと検査で拾えない。**検査用に出現率を上げて確かめられる口**を用意する
  （管理者モードの既存の仕組みを使ってよい）。
- `check-balance` の到達深度は「45秒で片付くか」で測っている。
  硬い敵が湧きに混じると、**掃除しきれずに死亡率が上がる**方向へ効く。
  過去に同じ理由でバランスが壊れた記録がある
  （`docs/SPEC.md`「逃げ回る型・硬い型を湧きの多数派にしない」）。
  0.5%なら影響は小さいはずだが、**数値で確かめて報告すること。**
